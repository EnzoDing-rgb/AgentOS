BoPO · 层级与互补

定义

Budget-Aware Agentic Routing via Boundary-Guided Training（Zhang et al., arXiv:2602.21227, 2026）。BoPO = Boundary-Guided Policy Optimization：按 agent step 做 RL 路由；训练 BoSFT，在线边界引导（如 GRPO）缓解稀疏奖励。

7.1 与本文的关系

BoPO 是单任务 step 级路由策略，在 BudgetFlow 中对应 ModelSelector 的可插拔实现。本文底座：全局账本（预留/结算）、硬预算与 RPM/并发准入、多 WF 调度、ZombieDetector。BoPO 脱离底座难解「多并发 + 同一全局预算」；底座可托管 RL，并保证硬约束。

7.2 SWE-bench 对齐场景

单轨迹：读 issue → 搜仓库 → … → 迭代；单任务预算如 $0.5，每步强/弱模型。BoPO：域内预训练，逐步按该任务剩余预算输出档位，奖励绑定该任务成败与花费。本文评测常为多实例并发（共享 Btotal），在全局就绪 call上系统级择优，优化汇总完成率。

7.3 BudgetFlow vs BoPO

维度BudgetFlow（本文）BoPO
优化目标共享硬预算 + 配额下全局任务完成率单任务预算–成功率 trade-off
决策视野全局账本 + 跨 workflow 就绪/排队单轨迹 + 该任务剩余预算
预算与配额预留—结算、硬上限、429/并发准入训练 soft-budget + 推理 BCD（非原子账本语义）
止损ZombieDetector、抢占、回收无对等机制
部署Training-free · 跨框架域专属训练 · 换域重训成本高
组合BoPO policy 可作 ModelSelector plug-in；BoPO 不替代全局治理层

7.4 BoPO 明确不覆盖（本文差分）

  • 多 agent 共享单一全局预算的跨任务分配与饥饿
  • 生产级 RPM / 并发 准入与 429 治理
  • 僵尸 / 无进度占用预算与槽位回收
  • 本地推理 / KV切换代价显式建模
  • 零域数据下免训练冷启动路由
