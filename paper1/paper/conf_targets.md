基准日：2026-07-22。
核心问题：一批任务共享同一个硬预算时，如何结合任务价值、智能体验证和软件工程验证，最大化总解决价值（TRV）。

## 下一步要改的两点（已拍板）

### 1. 重写 Related Work：按决策问题做 taxonomy，不按会议抬权重

正文 Related Work 改为分类写法。分类依据是**别人解决的决策问题**，不是最近扫到了哪些 AAAI 论文。新发现的近邻只按问题归入已有类别，不单独开“AAAI 近邻”段落，也不因其来源获得更高权重。

正式三类如下：

1. **单请求上的成本–质量选模**  
   已有：RouteLLM、Cascade Routing、RouteNLP、UCCI。  
   可补入：ZeroRouter、MODEL-SAT、ICL-Router、CP-Router。  
   共同点：为一条请求选择模型或决定是否升级；不处理任务之间的共享预算竞争。

2. **单任务 / 单段交互内部的预算控制**  
   已有：INTENT。  
   可补入：BAMAS、Online Multi-LLM、CCPO、STEER。  
   共同点：在一项任务或一段对话内部决定工具调用、换模、协作结构或是否继续；即使有预算，也是该项任务 / 该段交互自己的预算，不是多任务共用的硬预算。

3. **成本可计算的智能体运行实践**  
   只保留 **OpenSquilla**。  
   它是 token-efficient agent runtime，强调 cost-per-success、运行过程中的模型分层与可观测性。  
   **不进此类**：Claw-SWE-Bench（harness 公平评测协议，最多一句背景）、SWE-bench（测试平台）、vLLM / SGLang / Dynamo（执行层，可一句未来对接，不进 taxonomy）。

每类写完后统一落出缺口：这些工作分别优化单请求、单任务内控制，或单 agent 运行效率；**BudgetFlow** 研究多项任务如何争夺同一笔共享硬预算，并以执行前冻结的 Task Value 与验证后的 TRV 为目标。BudgetFlow 本身不是 Related Work 中的一类。

### 2. 在正文靠前位置新增系统框架图：把主 claim 创新画进主流程

**位置：** Introduction 末尾、贡献点之后、**Related Work 之前**。  
Related Work 开头可用一两句回指该图的决策单位。

**主流程（循环分配，不是一次性全局排程）：**

任务池（每项任务带冻结 Task Value、预计 token 需求、Model Fit）  
→ 读取批次剩余共享硬预算  
→ BudgetFlow 决定：下一项任务获得怎样的预算上限，以及是否获得强模型机会  
→ 智能体执行  
→ Verifier 判定是否解决  
→ 更新剩余预算与已验证 TRV  
→ 回到任务池，继续分配，直到预算耗尽或任务结束。

**图上要讲清的创新：** 决策箭头横跨**整批任务**。一个任务花掉预算，会改变后续任务可获得的机会。这是相对单请求选模、单任务内预算控制的核心差别。

**图上轻对照（不抢主图）：**  
左侧注单请求选模；中部注单任务内预算控制；主流程是跨任务共享硬预算分配。

**明确不进主图：** 记忆更新、步骤级切换、escalation、learned stop/continue。这些不是当前 Main Claim，按 `north_star.md` 放 future work。

**决策框对外只暴露：**  
输入 = 冻结 Task Value、预计 token 需求、Model Fit、剩余共享硬预算；  
输出 = 任务预算上限 / 是否给强模型机会；  
结算 = Verifier → 是否解决 → 更新剩余预算与 TRV。

<td>BAMAS</td>
<td><p>它研究的是：做<strong>一道题</strong>时，怎样在费用上限内，临时搭出一个多智能体小团队。先决定找哪些模型进这个小团队，再决定它们怎么协作：是一个接一个写、几个人同时写、一个人写另一个人挑错，还是有一个人专门当总指挥。</p><p><strong>举个例子。</strong> 现在有一道“写一个 Python 函数”的编程题，这道题本身只给你几百块钱预算。BAMAS 不会去想这道题和其他题谁更重要；它只盯着这道题，问：是让两个便宜模型一个写代码、一个检查，还是让一个贵一点的模型当总指挥、另一个模型去写？只要这道题自己不超预算就行。</p></td>
<td><p><strong>混合：整数规划 + 强化学习。</strong></p><p>选模型用整数线性规划，在预算内尽量挑更强的配置；选协作方式则用离线强化学习（类似 REINFORCE），在预先采好的轨迹上学习该用哪种拓扑。</p></td>
<td><p><strong>对照方法在干什么。</strong> AutoGen、MetaGPT、ChatDev 都是现成的多智能体工具：给你一道题，它们按固定套路拉起几个智能体一起做，但平时不太管花多少钱。作者又加了一个故意很简单的对照，叫 Naive-CostAware：钱多一点就多雇几个智能体，钱少就少雇几个，既不认真挑模型，也不认真挑协作方式。为了比得公平，这些对照都只能用和 BAMAS 一样的两种模型：贵一点的 DeepSeek-V3，或便宜一点的 GPT-4.1 nano。</p><p><strong>数据是什么。</strong> 三类题：小学到中学难度的数学应用题、短小的 Python 编程题、更难的数学竞赛题。每道题单独算一次费用，报告“做对了多少”和“平均花了多少钱”。预算也是按单道题设的，不是一整批题共用一个总预算。</p></td>
<td><p>BAMAS 管的是<strong>一道题内部</strong>怎么搭班底；BudgetFlow 管的是<strong>一整批软件工程任务</strong>共用一笔总预算时，下一笔贵模型机会该留给谁。BAMAS 追求单题做对且省钱；我们追求整批经过测试验证后的总解决价值尽量高。它报告的是每题平均费用，并没有让很多题去抢同一笔钱。</p></td>

<td>ZeroRouter</td>
<td><p>它研究的是：用户发来<strong>一条请求</strong>时，该把这条请求交给哪个模型；而且新模型上市后，路由器最好不要整套重训。</p><p><strong>举个例子。</strong> 客服系统里已经有五个模型。忽然上线第六个新模型。这时用户问：“这段合同有什么风险？”ZeroRouter 不会立刻重训整个路由器；它先让新模型做大约两百道代表性小测，摸清新模型大概能干嘛。摸清之后，再决定这条合同风险问题该给新模型、便宜模型，还是最贵最强的模型——取决于你此刻更在意答案质量、价格，还是响应速度。</p></td>
<td><p><strong>机器学习，不是强化学习。</strong></p><p>先用题目反应理论把“题难不难”和“模型强不强”拆开估计；再用 DistilBERT 把新请求映射到这个空间；最后按正确率、费用、延迟权重挑模型。核心是监督学习与表示学习，没有策略梯度或奖励优化回路。</p></td>
<td><p><strong>对照方法在干什么。</strong> MODEL-SAT 一类方法先给模型做能力测验，再按测验结果把问题分出去。RouteLLM 更简单：只在“强模型”和“弱模型”之间二选一，训练信号来自人类偏好。GraphRouter 把“题目类型、用户问题、候选模型”连成一张图，用图上的关系预测该连哪个模型。FORC 则先估每个模型答对这条问题的概率，再挑概率合适的那个。它们共同特点是：一次只处理一条请求，并选一个模型来答。</p><p><strong>数据是什么。</strong> 训练时见过的题，包括指令遵守、多步推理、数学、研究生级问答、通用知识等；训练时没见过的题，包括科学常识、测模型是否胡说、写代码。模型池很大：核心大约十个模型，另外还用五十个训练截止后才发布的新模型，专门测“新模型能不能接上”。比较时分别看：更在意正确率时怎么选、更在意省钱时怎么选、更在意响应快时怎么选。</p></td>
<td><p>ZeroRouter 问的是“这条请求交给谁”；BudgetFlow 问的是“这批任务里，谁值得消耗剩下的强模型机会”。它看的是问题文本和模型能力画像；我们看的是任务事先定好的价值、大概要花多少 token、模型是否适合这个任务、总预算还剩多少，以及测试有没有通过。它可以把“正确率、费用、延迟”按权重揉成一个总分；我们的总解决价值必须用执行前就冻结好的任务价值来结算，不能事后随意调权重。</p></td>
<td><ul>
<li>正文里把 ZeroRouter 写成“单条请求选模型”的代表，并写清三层：请求级选模型、任务级选模型、批次级分预算。</li>
<li>主结果旁直接列出五个策略各自用了多少便宜模型、多少强模型、总花了多少钱、总解决价值是多少，免得别人以为我们只是多花钱。</li>
<li>附录写明：学得的任务路由基线看不到任务价值，和 BudgetFlow 用的信息不一样。</li>
</ul></td>

<td>Online Multi-LLM Selection</td>
<td><p>它研究的是：用户和模型<strong>多轮对话</strong>时，每一步该换哪个模型。用户一说不满意，下一轮提示会被刚才的回答带着跑，系统事先猜不到后面会变成什么样；所以它只能边做边学，同时还要顾着<strong>这一条对话自己的费用上限</strong>。</p><p><strong>举个例子。</strong> 用户问一道数学题，便宜模型答错了。系统记下“不满意”，把错误答案和原题一起塞进下一轮，再决定要不要换一个更贵、更擅长数学的模型。整条对话最多试四次，钱也只能花这条对话自己的预算；省下来的钱不会自动留给下一位用户。</p></td>
<td><p><strong>在线学习 / 上下文赌博机，靠近强化学习。</strong></p><p>主算法是 LinUCB：每一步根据当前提示向量选模型，收到满意或不满意后再更新。预算感知版继续用费用归一化分数；位置感知版再用背包启发把贵模型尽量排到前几步。它不是离线训死一个路由器，而是边交互边学。</p></td>
<td><p><strong>对照方法在干什么。</strong> MetaLLM、MixLLM 都是“看一眼问题就先选定一个模型”的路由器：第一次选完，后面就算答错，也往往继续拿同一个模型重试。多数投票是同时问好几个模型，再按票数定答案。单模型对照则是全程只用某一个模型，不换。作者自己的方法不一样：答错之后，可以把上一轮答案并进上下文，并换一个新模型。所以它的优势不只是“第一次选得准”，还有“中途能改主意”。</p><p><strong>数据是什么。</strong> 四类题：更难的通用知识题、研究生级科学问答、竞赛数学题、普通数学题。每套题抽出一部分先热身，剩下的边做边评。候选池大约六个模型，有便宜的也有贵的。没有标准答案的题，就用另一个大模型当裁判说“对”或“不对”。每条查询的预算，是对照“完全不设预算时平均要花多少钱”再故意卡紧一点。</p></td>
<td><p>它的预算是<strong>单条对话自己的钱包</strong>：这条对话没花完，也不会转给别的对话。BudgetFlow 的预算是<strong>整批任务共用的一个钱包</strong>：这个任务多花一块钱，后面的任务就少一块钱。它每一步都能拿到“满意/不满意”的即时反馈；我们可信的反馈，主要是任务跑完后测试是否通过。它优化的是单条对话尽早答对；我们优化的是整批任务经过验证后的总解决价值。</p></td>
<td><ul>
<li>把三类记忆写清楚：各用什么记录更新、什么时候更新、下一次具体影响哪个决定——任务上限、选便宜还是强模型、继续还是停。</li>
<li>从现有运行记录画一张“批次花钱轨迹”：按任务顺序看累计花费、剩余预算、用了几次强模型、最后测试过没过。这样别人一眼能看出：共享预算确实改变了后面的决策。</li>
</ul></td>

<td>CCPO</td>
<td><p>它研究的是：做<strong>一道题</strong>时，怎样在“答案要足够可靠”的前提下尽量少花钱。系统手里有便宜模型和贵模型，也可以查资料；每一步要决定是先交便宜答案、花钱请贵模型帮忙，还是再查一轮资料再试。</p><p><strong>举个例子。</strong> 有一道需要查百科才能答的多跳问答。系统可以先让便宜模型去查资料并作答；如果还是没把握，再花钱请贵模型来看，或者再查一轮。最多试四轮。CCPO 要学的是：怎样安排这些动作，才能达到你事先要求的可靠程度，而不是一上来就请最贵的模型。</p></td>
<td><p><strong>强化学习。</strong></p><p>用约束策略优化（CPO）学“这一轮交便宜答案、请贵模型，还是再查资料”。关键点是把共形预测嵌进优化，让可靠性约束一边训练一边卡住，而不是训完后再事后贴阈值。</p></td>
<td><p><strong>对照方法在干什么。</strong> Random 是随机挑动作。提示式大模型策略是直接让大模型看现场情况后决定下一步。LLM-EXIT 是同一个模型既负责答题，又负责决定“要不要再来一轮”。UALA 不学习策略，而是看不确定性分数有没有超过固定门槛，再决定继续还是交卷。CPO 一类方法会学策略，但普通版不带“可靠性保证”；有的是训完后再贴一层保证，有的是边学边加。作者还拿“全程只用贵模型再决定何时退出”“全程只用便宜模型再决定何时退出”当费用边界。</p><p><strong>数据是什么。</strong> 两类题：需要连查几段资料才能答的多跳问答，以及覆盖很多学科的选择题。训练、校准、测试分开；每道题最多四轮。主指标是总花费、答案是否达到事先要求的可靠程度、平均试了几轮、最终给出多少个候选答案。</p></td>
<td><p>CCPO 的硬要求是：这道题的答案要够可靠。BudgetFlow 的硬要求是：整批任务的总预算不能超。它先定可靠性，再省钱；我们先定总预算，再按任务价值决定稀缺机会给谁。它在一道题内部排底座模型、引导模型、查资料；我们在很多任务之间排谁该用强模型、谁该停。它没有“这道题比那道题更值钱”这种事先登记的任务价值，也没有跨任务抢预算这件事。</p></td>
<td><ul>
<li>相关工作里写一句就够：CCPO 管的是“单题既要可靠又要省钱”，我们管的是“一批任务共用硬预算时怎么按价值分配”。</li>
<li>主结果表旁明确标出：所有策略是否都守住了共享硬预算。预算变紧变松时，把“预算有没有守住”和总解决价值放在一起报，不要只当脚注。</li>
</ul></td>
</tr>
<tr>
<td>STEER</td>
<td><p>它研究的是：解<strong>一道题</strong>时，推理过程可以按步骤拆开。大部分步骤让小模型写；只有小模型对“下一步”没把握时，才让大模型接手这一步。它不训练额外的路由器，也不依赖专门的过程打分模型，主要看小模型自己写这一步时有多自信。</p><p><strong>举个例子。</strong> 解一道很难的数学竞赛题。小模型前两步代数推导很顺利；到第三步，它对接下来怎么变形把握很低。STEER 就只让大模型重写第三步；后面如果小模型又有把握了，就继续让小模型写。它关心的是<strong>同一道题内部</strong>怎样少用大模型，而不是这道题和其他题谁更值得花钱。</p></td>
<td><p><strong>启发式为主。</strong></p><p>不训练额外路由器，也不做强化学习。它看小模型写每一步时的输出置信，再用高斯混合把置信分数分成“有把握 / 没把握”，低置信就换大模型。阈值靠网格搜索挑，本质是规则加统计校准，不是学得策略。</p></td>
<td><p><strong>对照方法在干什么。</strong> RSD 也是一步一步来：先让小模型起草，再用一个专门训练过的“过程打分模型”给这一步打分；分数低才让大模型重写。另一种对照更粗：读完题目后就把整道题交给小模型或大模型，中途不再换。SpecReason 也是按步骤切换，但不用过程打分模型，而是请大模型当裁判说这一步行不行。所有方法都会扫一遍阈值，取表现最好的阈值再比。</p><p><strong>数据是什么。</strong> 数学题用常见数学基准和竞赛题；更广的推理题包括多跳问答、规划和逻辑题。模型既有通用指令模型，也有专门练过数学的模型。费用主要按计算量估算，不是直接报美元账单；同时报正确率和“正确率相对计算量划不划算”。</p></td>
<td><p>STEER 问的是“这一步还让小模型写，还是换成大模型”；BudgetFlow 问的是“下一次强模型机会，该给批次里的哪一项任务”。前者发生在一道题的推理过程里，后者发生在很多任务之间。它靠的是小模型写每一步时的自信程度；我们靠的是任务价值、大概要花多少 token、模型是否适合、总预算还剩多少，以及任务结束后测试过没过。它主要报计算量和正确率；我们主要报美元花费、预算有没有守住，以及经过验证的总解决价值。</p></td>
<td><ul>
<li>相关工作里用一两句划清：STEER 是“一道题内部按步骤在小模型和大模型之间切换”，我们是“一批任务之间按价值和共享预算分配机会”。</li>
<li>决策审计里分开写两件事：任务开始时选了便宜模型还是强模型；任务进行中有没有再升级。主结果继续以解决数、总解决价值、总花费、每美元解决价值为主。</li>

## 附录 B. 五篇 AAAI 近邻论文详解

以下内容保留此前读 PDF 后整理出的详细笔记。正文主表现已纳入五篇；这里继续保留完整深读信息，供写相关工作和边界说明时查细节。

### BAMAS：Structuring Budget-Aware Multi-Agent Systems

**研究问题是什么。**
现有多智能体框架（如 AutoGen、MetaGPT、ChatDev）主要追求把任务做对，对「整套系统花多少钱」控制很弱：一次任务里多个智能体反复调大模型，费用会随协作方式和调用深度变化，很难事先卡死。BAMAS 要回答的问题是：给定一个任务、一批可选大模型、以及一个明确的费用上限，怎样搭出一套多智能体系统，既尽量做对题，又严格不超预算。作者把它拆成两件事：先决定「在预算内选哪些大模型」，再决定「这些大模型用什么协作结构一起干活」。

**对照方法用的是什么。**
- 主对照（回答费用–效果）：AutoGen、MetaGPT、ChatDev。这些方法本身不带「先选模型再选拓扑」的预算模块，所以作者把它们分别固定成只用 DeepSeek-V3、或只用 GPT-4.1 nano 两套实现，再和 BAMAS 比。MATH 上费用更高，基线只报 GPT-4.1 nano，以控制实验开销。
- 消融对照（回答组件是否必要）：Naive-CostAware。它按五个预设资源档位贪心增加大模型个数（第 i 档用 i+1 个模型，至少两个），不做整数线性规划全局选模型，也不做拓扑选择策略学习。

**数据集用的是什么。**
- GSM8K：数学应用题。用训练集前 1000 题做强化学习训练语料，在完整测试集 1319 题上评测。
- MBPP：Python 编程题。用训练集全部 374 题做训练语料，在 500 题测试集上评测。
- MATH：更难的数学题。按难度与题型分层抽样，构造各 1000 题的训练/测试集，保持原分布。
可用模型池主要是两种：DeepSeek-V3（更强更贵）和 GPT-4.1 nano（更弱更便宜）。GSM8K 与 MBPP 的预算档从约 500 到 2000；MATH 从约 1000 到 3000。

**实验怎么设计。**
流程固定三步。
1. 费用约束下的模型配置：把「选哪些大模型」写成整数线性规划，目标是在预算内尽量选更强的配置，并至少选两个模型，以保证是多智能体而不是单模型。
2. 协作拓扑选择：在线性、星形、反馈修订、中心规划者驱动等几种固定拓扑库里，用离线强化学习学一个策略，根据任务和预算选一种拓扑。奖励同时看「有没有做对」和「花了多少钱、有没有超预算」；超预算重罚，做对且省钱才给额外奖励。因为在线采轨迹太贵，策略在预先采集的离线数据上用类 REINFORCE 方式训练。
3. 实例化执行：把选中的模型按拓扑角色装上去（例如反馈拓扑里更强的模型当批评者，其余当执行者），再跑完整任务。
评测指标是正确率，以及按输入、输出 token 单价算出来的平均费用。研究问题分三条：相对现有多智能体构建方法的费用–效果；相对贪心费用策略，选模型与选拓扑两个组件是否必要；拓扑选择会不会随任务和预算变化。

**得到的结论是什么。**
在三个数据集上，BAMAS 在给定预算下可以达到与 AutoGen、MetaGPT、ChatDev 相近甚至更高的正确率，同时平均费用明显更低；作者报告费用最多可降约 86%，并且实际花费能卡在预设预算内。消融显示，相对 Naive-CostAware，联合做模型配置与拓扑选择更好。拓扑分布上，预算紧时更常选简单拓扑；预算更宽时，拓扑选择会随数据集（任务类型）变化。

**对我们有没有启示。**
有，主要是定位和写法，不是要照抄他们的两套优化器。
1. 相关工作里应明确写：BAMAS 解决的是「单个任务内部、在费用上限下如何选模型与协作结构」；BudgetFlow 解决的是「一批任务共用一个硬预算时，稀缺模型机会按任务价值如何分配」。这是同会审稿人最容易对齐的分层。
2. 报告习惯可对齐：同时报正确率（或解决数）与花费，并展示多档预算下的费用–效果曲线；我们主线对应的是 TRV、Resolved Rate、花费，以及固定共享硬预算。
3. 不必把整数线性规划选模型、离线强化学习选拓扑搬进我们的主实验；那是另一层机制，也不是可以顺手补上的小实验。

### ZeroRouter：Breaking Model Lock-in（零样本大模型路由）

**研究问题是什么。**
大模型越来越多，现有路由器常常绑死在「训练时见过的那几个模型」上：要加新模型，往往要重新采偏好数据、重新训练整套路由逻辑，作者把这叫 model lock-in。ZeroRouter 要解决的问题是：怎样做一个路由系统，既能按准确率、费用、延迟做多目标选择，又能在几乎不重训整机的情况下，把新发布的模型接进来（零样本接入），并且在训练时没见过的任务集合上仍然可用。

**对照方法用的是什么。**
四个近期路由方法：
1. CIT-LLM-Routing：用「能力指令微调和能力测试」去预测各模型表现，再做路由。
2. RouteLLM：用人类偏好数据学一个二选一路由器，在强模型和弱模型之间做选择。
3. GraphRouter：把任务、查询、模型建成异构图，把路由做成边预测。
4. FORC：先用预训练元模型预测每个模型对当前查询的准确率，再据此选模型。

**数据集用的是什么。**
一共九套基准，分成训练阶段见过的分布内集合，和训练阶段没见过的分布外集合。
- 分布内六套：IFEval（按指令办事）、BBH（多步推理难题）、MATH（高等数学）、GPQA（研究生级问答）、MuSR（多步推理）、MMLU-PRO（更难的多任务语言理解）。
- 分布外三套：ARC-C（科学选择题）、TruthfulQA（是否编造错误事实）、HumanEval（代码生成）。
模型池很大：评测里用了约 60 个大模型。其中约 10 个覆盖从约 1B 到约 235B 的核心集合，用来测常规路由；另外约 50 个是路由训练数据截止之后才发布的模型，专门用来验证「新模型不重训整机也能接进来」。

**实验怎么设计。**
方法分三块。
1. 通用潜在空间：用类似题目反应理论（多维 2PL IRT）的概率模型，把「这道题本身有多难、区分度如何」和「某个模型能力有多强」拆开估计。题侧参数尽量与具体模型无关，这样新模型只要在少量锚点题上测一遍，就能估出它的能力剖面。锚点题用信息论里的 D-最优准则贪心挑选，尽量用尽量少的题把模型能力估准。潜在空间标定用了 Open LLM Leaderboard 上大量模型在分布内集合上的评测结果（文中写用 py-irt，潜在维约 20）。
2. 上下文感知预测器：用 DistilBERT（约 6600 万参数）把原始查询文本直接映射到上述潜在坐标，这样推理时不必再对每个候选模型做穷尽试跑。
3. 双模式、策略驱动优化：把准确率、费用、延迟合成一个总奖励，用三组权重分别对应「尽量准」「尽量省钱」「尽量低延迟」。
实现上预测器在单张 NVIDIA A800（80GB）上微调约 40 个 epoch。比较时同时看分布内与分布外，并按小规模模型（约小于 20B）与更大规模模型分组报告。

**得到的结论是什么。**
在分布内数据上，ZeroRouter 在「尽量准」「尽量省钱」「尽量低延迟」三组目标下，相对四个基线往往同时更好，而不是只在某一个目标上交换。在分布外三套任务上，优势更明显：作者报告大规模模型组的最高准确率约为 0.68，而最强基线约为 0.62；同时，在最低费用和最低延迟目标上，ZeroRouter 也更好。消融表明，用 D-最优方法选择锚点题，比随机抽样、只按难度选题或只按区分度选题更有效。总结论是：把「查询难不难」和「模型强不强」拆开表示之后，路由就不必过度绑定固定模型名单；新模型可以通过少量锚点评测接入，对未见任务集合也更稳。

**对我们有没有启示。**
几乎没有机制上的启示；有一点引用层面的提醒。
1. 它再次说明 AAAI 审稿人熟悉「查询级、多目标路由」这条线，所以我们正文里需要有只用便宜模型、只用最强模型、学得路由或静态路由等对照，并把决策单位写成「批次任务」而不是「单条查询」。
2. 他们的核心贡献——六十模型池、IRT 潜在空间、新模型零样本接入——不是 BudgetFlow 要解决的问题，也不是当前主线实验该扩的方向。
3. 诚实结论：不要为对齐 ZeroRouter 去重跑大模型池或接入潜在空间路由；最多在相关工作里把它列为查询级路由代表。

### STEER：Confidence-Guided Stepwise Model Routing

**研究问题是什么。**
推理型大模型很贵：模型更大，每生成一个 token 的计算量更高；再加上自洽解码、搜索、加长推理等测试时技巧，单题生成的 token 数还会再涨。已有省钱办法多半是：训练一个外部路由器，把整道题分给小模型或大模型。问题是，这类路由器换到别的领域容易变差，而且为了得到「这道题该上谁」的训练标签，往往要做很贵的采样。另一些工作把路由做到推理步骤级别，但依赖额外训练好的过程奖励模型，过程奖励模型又常常只在数学、且只对某类模型可靠。STEER 要做的是：在不依赖外部训练好的路由模块或过程奖励模型的前提下，在推理的每一步决定「这一步继续让小模型写，还是交给大模型写」，从而在多种推理任务上同时保住正确率并降低计算量。

**对照方法用的是什么。**
分成两组。
- 依赖外部训练模块：
  1. RSD：每一步先让小模型起草，再用过程奖励模型给这一步打分；分数低于阈值才让大模型重写。作者用 Skywork-o1-PRM 7B，该过程奖励模型是在 Qwen2.5-Math-Instruct 上训练的。
  2. Damani 等人（2025）的问题级分配：训练一个轻量难度估计器，在读完题目后就把整道题的全部推理交给小模型或大模型，中途不再换。
- 不依赖外部训练模块：SpecReason。步骤级做法接近 RSD，但步骤好坏不是过程奖励模型打的，而是用大模型当裁判来打分。
所有方法（含 STEER）都对阈值做步长 0.1 的网格搜索，取表现最好的阈值再比，保证对照公平。

**数据集用的是什么。**
- 数学推理：MATH500、OmniMath、以及 2022–2025 年的 AIME 题。MATH500 与 OmniMath 带人工难度标注，方便按难度分析。
- 更广的推理：MuSiQue（多跳问答）、ACPBench 的选择题部分（动作与规划推理）、KOR-Bench 里的 Cipher、Counterfactual、Logic 子集（排除 Operation，因为它太像数学；排除 Puzzles，因为各模型正确率都太低）。
模型方面同时测通用指令模型（Gemma3-Instruct、Qwen2.5-Instruct）和数学特化模型（Qwen2.5-Math-Instruct）。数学基准上不用正确率过低的 Qwen2.5-Instruct；非数学基准上不用会在非数学任务上出现文本退化的 Qwen2.5-Math-Instruct。推理一步定义为按 `\n\n` 切开的文本段。推理后端用 vLLM，温度 0.7。

**实验怎么设计。**
核心信号来自小模型：在生成某一步之前，从它的输出分布（logits）算出这一步的置信分数；再用高斯混合模型把置信分数校准成「这一步可不可靠」的判断。若小模型对当前步不够有把握，这一步改由大模型生成；否则继续用小模型。算法上会先根据第一步置信把题目分成「小模型可扛」和「需要大模型修订」两类，再在后续步骤里按双方置信与阈值继续分流，直到各题推理结束或达到最大步数。费用用标准 Transformer 估算：约 N 个参数时，每个推理 token 约 2N 次浮点运算；报告每题平均 FLOPs，以及正确率除以 FLOPs 的比值，用来同时看效果和开销。

**得到的结论是什么。**
在数学推理上，STEER 能接近或超过「全程只用大模型」的正确率，同时明显少算；作者报告在 AIME 上相对全程大模型大约多 20% 正确率，并少约 48% 的 FLOPs。在更广的推理任务上，它也常给出最好的正确率–计算量权衡。相对依赖过程奖励模型的 RSD：当过程奖励模型的训练分布与当前模型/任务不一致时（例如过程奖励模型训在 Qwen 数学模型上，却拿去评 Gemma），RSD 正确率会掉，有时甚至比全程大模型更费，因为一步被拒后等于小模型和大模型都跑过。问题级路由器能省算力，但在部分模型与任务上正确率掉得更多，或几乎总是把题扔给大模型。总结论：用小模型自身的逐步置信分数做步骤级切换，可以少依赖外部训练模块，在换模型族、换任务域时更稳，并且在正确率与计算量之间取得可用的折中。

**对我们有没有启示。**
没有。
STEER 关注的是「一道题的推理过程里，每一步用小模型还是大模型」；BudgetFlow 关注的是「一批软件工程任务共用硬预算时，下一笔机会给哪个任务、是否上更强模型档」。两者决策单位不同，信号也不同：前者用逐步 logits 置信，后者用任务价值、估计 token 需求、模型匹配和预算压力。因此，不要加逐步置信路由实验；相关工作里如需提及，只用来划清边界，一句话即可。

### CCPO：Conformal Constrained Policy Optimization for Cost-Effective LLM Agents

**研究问题是什么。**
单个大模型又贵又未必稳；人会在「再试一次」「换更强模型」「直接交卷」之间做权衡。CCPO 把这件事做成智能体编排：策略在若干轮里编排「便宜但不准的底座模型」和「贵但更准的引导模型」（文中底座用 LLaMA，引导用 GPT-4o），并可调用检索等工具。目标不是「尽量准就行」，而是：在用户指定的可靠性水平 α 下，**最小化期望费用**；可靠性用共形预测写成可检验的覆盖率约束（预测集合要盖住真答案，或判定该题不可解）。

**对照方法用的是什么。**
两组。
- 智能体与启发式方法：Random（在动作集上均匀抽）；把策略网络换成提示过的大模型（GPT-4o 或 LLaMA）；LLM-EXIT（同一模型既答题又决定要不要再来一轮）；GPT-4o 引导的 UALA（用固定不确定性阈值选动作，而不是学习策略）。
- 策略学习：普通 CPO（约束策略优化，但无共形）；CPO batch（训完后在校准集上做批次共形定阈值）；CPO online（用在线共形把随机策略收成有覆盖保证的策略）。CCPO 的差别是把共形预测**嵌进**约束策略优化，而不是训完再贴一层阈值。

**数据集用的是什么。**
- HotpotQA：多跳常识问答，工具侧跟 UALA 一样用 Wikipedia 检索；训练约 1000 题，校准与测试各约 200。
- MMLU：多选学科问答；训练约 560，校准与测试各约 200。原 UALA 用 Google API 当工具，但单价太高（文中写约每千次 5 美元），作者改成思维链采样（第一步温度 0，后续温度 1）。
模型：底座 LLaMA-2-7B（8-bit）或 LLaMA-3.2-3B；引导 GPT-4o。回合上限 T=4；可靠性 α 主报告 0.1（部分更强底座用更严的 0.05）。

**实验怎么设计。**
每轮策略在「交底座答案」「交引导答案」「再查工具或再试」这一类动作里选择；共形侧维护自适应阈值 κ，并与费用感知策略联合更新。策略网络是三层、每层 64 个隐单元的小网络，从头训练约 1500–2000 步。主指标包括累计 API/计算费用（美分）、覆盖率、平均回合长度、预测集合大小。作者还在 100 次随机划分上画覆盖率与费用箱线图，检查结果是否稳定在目标 α 附近。

**得到的结论是什么。**
在 HotpotQA 与 MMLU 上，CCPO 能在达到目标覆盖率的同时，相对最强的费用感知对照把总费用再压一截；作者报告相对一批费用感知与大模型引导方法，费用最多约降 30%。相对 CPO batch 和 CPO online 这类「先训策略再贴共形」的做法，把共形嵌进优化通常更能同时卡住覆盖与费用。总结论是：多智能体式「底座 + 引导」编排，可以在显式可靠性约束下做费用最小化，而不只是事后调阈值。

**对我们有没有启示。**
有定位启示，没有该搬过来的优化器。
1. AAAI 审稿人已经见过「智能体编排 + 费用最小化 + 可靠性/覆盖约束」；BudgetFlow 要写清自己的约束是批次共享硬预算、预注册任务价值、以及验证型解决，不是单题共形覆盖率 α。
2. 报告习惯可对齐：同时报告费用与「约束是否满足」。他们报告覆盖率；我们报告预算是否守住、TRV 和解决数。
3. 不要把 CCPO 的共形阈值或 CPO 训练搬进主线；那是单题智能体编排层，不是批次价值分配。

### Online Multi-LLM Selection：上下文赌博机下的在线多模型选择

**研究问题是什么。**
用户查询会被多步修改：上一步模型答完后，提示会按黑盒过程变化，无法可靠模拟或预测未来上下文。作者要在这种「上下文无结构演化」下，在线、逐步挑选该调用哪个大模型，并且不依赖离线路由训练集，也不查看模型内部。进一步，他们加入了预算感知扩展（每轮有费用上限，费用随机）和位置感知启发（更希望前几步就答对）。

**对照方法用的是什么。**
单步上下文赌博机路由器 MetaLLM、MixLLM，以及多数投票；再与候选池里各单模型比。公平起见，所有方法都允许多步（最多 H=4）；基线路由器失败后按原设计**重试同一初次选择**，而他们的方法每步可换模型。

**数据集用的是什么。**
四套：MMLU-Pro、GPQA（偏知识）、AIME、Math500（偏数学推理）。无离散标签的题用 DeepSeek-R1 当裁判给对错。每套随机 20% 初始化、80% 在线评测。候选池约六个模型，跨能力与单价，文中点名包括 Llama-4-Maverick、Gemini-2.0-Flash、Mistral-Small-3.1，以及 Phi-4、GPT-4.1-Nano、DeepSeek-V3 等。查询用 384 维 BGE 嵌入。预算感知变体的每查询预算，相对「无预算约束的贪心 LinUCB」平均花费来定，故意卡紧。

**实验怎么设计。**
主算法是基于 LinUCB 的上下文赌博机，优化「短视遗憾」（myopic regret），证明可不预测未来上下文仍有次线性遗憾。预算感知版在剩余预算内用费用归一化的乐观分数选臂；再提出 PAKH（位置感知背包启发），把高置信、可能更贵的模型尽量排到前几步，避免纯贪心总捡便宜弱模型。主看正确率与费用；图上占「同等费用更高正确率」的左上区域更好。

**得到的结论是什么。**
在线方法相对 MetaLLM、MixLLM 和多数投票，在正确率–费用权衡上更好。PAKH 在难推理集上尤其强：文中报告 AIME 约 62.50%、GPQA 约 66.67%；全任务平均下来，相对最强路由基线 MixLLM，它正确率更高且更省钱。无预算的贪心 LinUCB 在 MMLU-Pro、Math500 上正确率最高，说明「先追求准」与「卡预算」是不同工作点。总结论是：在提示黑盒演化、只能拿在线反馈时，上下文赌博机可以做自适应、费用敏感的多模型选择。

**对我们有没有启示。**
有一点对照命名启示，机制不用搬。
1. 他们的「预算」是单查询多步上的费用上限；我们的是一批任务共享的硬预算。相关工作必须写清这两层，避免审稿人以为我们在做同一问题。
2. 「在线反馈更新选模」可提醒我们：如果写学习回路，要强调我们消费的是验证框架可信的任务级记录，也就是费用记忆、路由记忆和升级记忆，而不是他们的逐步赌博机反馈。
3. 不必复现六模型在线赌博机实验；主线保持固定任务集与冻结价值即可。
