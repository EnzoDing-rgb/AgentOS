### 1.1.1 三篇 AAAI 近邻论文详解

下面按人话讲清 BAMAS、ZeroRouter、STEER 各自在研究什么、怎么评、得出什么结论。内容依据本地 PDF 正文，不是摘要复读。

#### BAMAS：Structuring Budget-Aware Multi-Agent Systems

**研究问题是什么。**  
现有多智能体框架（如 AutoGen、MetaGPT、ChatDev）主要追求把任务做对，对「整套系统花多少钱」控制很弱：一次任务里多个智能体反复调大模型，费用会随协作方式和调用深度变化，很难事先卡死。BAMAS 要回答的问题是：给定一个任务、一批可选大模型、以及一个明确的费用上限，怎样搭出一套多智能体系统，既尽量做对题，又严格不超预算。作者把它拆成两件事：先决定「在预算内选哪些大模型」，再决定「这些大模型用什么协作结构一起干活」。

**Baseline 用的是什么。**  
- 主对照（回答费用–效果）：AutoGen、MetaGPT、ChatDev。这些方法本身不带「先选模型再选拓扑」的预算模块，所以作者把它们分别固定成只用 DeepSeek-V3、或只用 GPT-4.1 nano 两套实现，再和 BAMAS 比。MATH 上费用更高，基线只报 GPT-4.1 nano，以控制实验开销。  
- 消融对照（回答组件是否必要）：Naive-CostAware。它按五个预设资源档位贪心增加大模型个数（第 i 档用 i+1 个模型，至少两个），不做整数线性规划全局选模型，也不做拓扑选择策略学习。

**数据集用的是什么。**  
- GSM8K：数学应用题。用训练集前 1000 题做强化学习训练语料，在完整测试集 1319 题上评测。  
- MBPP：Python 编程题。用训练集全部 374 题做训练语料，在 500 题测试集上评测。  
- MATH：更难的数学题。按难度与题型分层抽样，构造各 1000 题的训练/测试集，保持原分布。  
可用模型池主要是两种：DeepSeek-V3（更强更贵）和 GPT-4.1 nano（更弱更便宜）。GSM8K / MBPP 的预算档从约 500 到 2000；MATH 从约 1000 到 3000。

**实验怎么设计。**  
流程固定三步。  
1. 费用约束下的模型配置：把「选哪些大模型」写成整数线性规划，目标是在预算内尽量选更强的配置，并至少选两个模型，以保证是多智能体而不是单模型。  
2. 协作拓扑选择：在线性、星形、反馈修订、中心规划者驱动等几种固定拓扑库里，用离线强化学习学一个策略，根据任务和预算选一种拓扑。奖励同时看「有没有做对」和「花了多少钱、有没有超预算」；超预算重罚，做对且省钱才给额外奖励。因为在线采轨迹太贵，策略在预先采集的离线数据上用类 REINFORCE 方式训练。  
3. 实例化执行：把选中的模型按拓扑角色装上去（例如反馈拓扑里更强的模型当批评者，其余当执行者），再跑完整任务。  
评测指标是正确率，以及按输入/输出 token 单价算出来的平均费用。研究问题分三条：相对现有多智能体构建方法的费用–效果；相对贪心费用策略，选模型与选拓扑两个组件是否必要；拓扑选择会不会随任务和预算变化。

**得到的结论是什么。**  
在三个数据集上，BAMAS 在给定预算下可以达到与 AutoGen / MetaGPT / ChatDev 相近甚至更高的正确率，同时平均费用明显更低；作者报告费用最多可降约 86%，并且实际花费能卡在预设预算内。消融显示，相对 Naive-CostAware，联合做模型配置与拓扑选择更好。拓扑分布上，预算紧时更常选简单拓扑；预算更宽时，拓扑选择会随数据集（任务类型）变化。

#### ZeroRouter：Breaking Model Lock-in（零样本大模型路由）

**研究问题是什么。**  
大模型越来越多，现有路由器常常绑死在「训练时见过的那几个模型」上：要加新模型，往往要重新采偏好数据、重新训练整套路由逻辑，作者把这叫 model lock-in。ZeroRouter 要解决的问题是：怎样做一个路由系统，既能按准确率、费用、延迟做多目标选择，又能在几乎不重训整机的情况下，把新发布的模型接进来（零样本接入），并且在训练时没见过的任务集合上仍然可用。

**Baseline 用的是什么。**  
四个近期路由方法：  
1. CIT-LLM-Routing：用「能力指令微调 / 能力测试」去预测各模型表现，再路由。  
2. RouteLLM：用人类偏好数据学一个二选一路由器（强模型 vs 弱模型）。  
3. GraphRouter：把任务、查询、模型建成异构图，把路由做成边预测。  
4. FORC：先用预训练元模型预测每个模型对当前查询的准确率，再据此选模型。

**数据集用的是什么。**  
一共九套基准，分成训练阶段见过的分布内集合，和训练阶段没见过的分布外集合。  
- 分布内六套：IFEval（按指令办事）、BBH（多步推理难题）、MATH（高等数学）、GPQA（研究生级问答）、MuSR（多步推理）、MMLU-PRO（更难的多任务语言理解）。  
- 分布外三套：ARC-C（科学选择题）、TruthfulQA（是否编造错误事实）、HumanEval（代码生成）。  
模型池很大：评测里用了约 60 个大模型。其中约 10 个覆盖从约 1B 到约 235B 的核心集合，用来测常规路由；另外约 50 个是路由训练数据截止之后才发布的模型，专门用来验证「新模型不重训整机也能接进来」。

**实验怎么设计。**  
方法分三块。  
1. 通用潜在空间：用类似题目反应理论（多维 2PL IRT）的概率模型，把「这道题本身有多难、区分度如何」和「某个模型能力有多强」拆开估计。题侧参数尽量与具体模型无关，这样新模型只要在少量锚点题上测一遍，就能估出它的能力剖面。锚点题用信息论里的 D-最优准则贪心挑选，尽量用尽量少的题把模型能力估准。潜在空间标定用了 Open LLM Leaderboard 上大量模型在分布内集合上的评测结果（文中写用 py-irt，潜在维约 20）。  
2. 上下文感知预测器：用 DistilBERT（约 6600 万参数）把原始查询文本直接映射到上述潜在坐标，这样推理时不必再对每个候选模型做穷尽试跑。  
3. 双模式 / 策略驱动优化：把准确率、费用、延迟合成一个总奖励，用三组权重分别对应「尽量准」「尽量省钱」「尽量低延迟」。  
实现上预测器在单张 NVIDIA A800（80GB）上微调约 40 个 epoch。比较时同时看分布内与分布外，并按小规模模型（约小于 20B）与更大规模模型分组报告。

**得到的结论是什么。**  
在分布内数据上，ZeroRouter 在「尽量准 / 尽量省 / 尽量低延迟」三组目标下，相对四个基线往往同时更好，而不是只在某一个目标上交换。在分布外三套任务上，优势更明显：作者报告例如大规模模型组上 Max-Acc 约 0.68，对上最强基线约 0.62，同时在 Min-Cost、Min-Lat 上也更好。消融表明，用 D-最优选锚点题比随机抽样、只按难度或只按区分度选点更有效。总结论：把「查询难不难」和「模型强不强」拆开表示之后，路由可以少绑死在固定模型名单上，新模型可用少量锚点评测接入，并且对未见任务集合更稳。

#### STEER：Confidence-Guided Stepwise Model Routing

**研究问题是什么。**  
推理型大模型很贵：模型更大，每生成一个 token 的计算量更高；再加上自洽解码、搜索、加长推理等测试时技巧，单题生成的 token 数还会再涨。已有省钱办法多半是：训练一个外部路由器，把整道题分给小模型或大模型。问题是，这类路由器换到别的领域容易变差，而且为了得到「这道题该上谁」的训练标签，往往要做很贵的采样。另一些工作把路由做到推理步骤级别，但依赖额外训练好的过程奖励模型，过程奖励模型又常常只在数学、且只对某类模型可靠。STEER 要做的是：在不依赖外部训练好的路由模块或过程奖励模型的前提下，在推理的每一步决定「这一步继续让小模型写，还是交给大模型写」，从而在多种推理任务上同时保住正确率并降低计算量。

**Baseline 用的是什么。**  
分成两组。  
- 依赖外部训练模块：  
  1. RSD：每一步先让小模型起草，再用过程奖励模型给这一步打分；分数低于阈值才让大模型重写。作者用 Skywork-o1-PRM 7B，该过程奖励模型是在 Qwen2.5-Math-Instruct 上训练的。  
  2. Damani 等人（2025）的问题级分配：训练一个轻量难度估计器，在读完题目后就把整道题的全部推理交给小模型或大模型，中途不再换。  
- 不依赖外部训练模块：SpecReason。步骤级做法接近 RSD，但步骤好坏不是过程奖励模型打的，而是用大模型当裁判来打分。  
所有方法（含 STEER）都对阈值做步长 0.1 的网格搜索，取表现最好的阈值再比，保证对照公平。

**数据集用的是什么。**  
- 数学推理：MATH500、OmniMath、以及 2022–2025 年的 AIME 题。MATH500 与 OmniMath 带人工难度标注，方便按难度分析。  
- 更广的推理：MuSiQue（多跳问答）、ACPBench 的选择题部分（动作与规划推理）、KOR-Bench 里的 Cipher / Counterfactual / Logic 子集（排除 Operation，因太像数学；排除 Puzzles，因各模型正确率都太低）。  
模型方面同时测通用指令模型（Gemma3-Instruct、Qwen2.5-Instruct）和数学特化模型（Qwen2.5-Math-Instruct）。数学基准上不用正确率过低的 Qwen2.5-Instruct；非数学基准上不用会在非数学任务上出现文本退化的 Qwen2.5-Math-Instruct。推理一步定义为按 `\n\n` 切开的文本段。推理后端用 vLLM，温度 0.7。

**实验怎么设计。**  
核心信号来自小模型：在生成某一步之前，从它的输出分布（logits）算出这一步的置信分数；再用高斯混合模型把置信分数校准成「这一步可不可靠」的判断。若小模型对当前步不够有把握，这一步改由大模型生成；否则继续用小模型。算法上会先根据第一步置信把题目分成「小模型可扛」和「需要大模型 refining」两类，再在后续步骤里按双方置信与阈值继续分流，直到各题推理结束或达到最大步数。费用用标准 Transformer 估算：约 N 个参数时，每个推理 token 约 2N 次浮点运算；报告每题平均 FLOPs，以及正确率除以 FLOPs（A/F），用来同时看效果和开销。

**得到的结论是什么。**  
在数学推理上，STEER 能接近或超过「全程只用大模型」的正确率，同时明显少算；作者报告在 AIME 上相对全程大模型大约多 20% 正确率，并少约 48% 的 FLOPs。在更广的推理任务上，它也常给出最好的正确率–计算量权衡。相对依赖过程奖励模型的 RSD：当过程奖励模型的训练分布与当前模型/任务不一致时（例如过程奖励模型训在 Qwen 数学模型上，却拿去评 Gemma），RSD 正确率会掉，有时甚至比全程大模型更费，因为一步被拒后等于小模型和大模型都跑过。问题级路由器能省算力，但在部分模型与任务上正确率掉得更多，或几乎总是把题扔给大模型。总结论：用小模型自身的逐步置信分数做步骤级切换，可以少依赖外部训练模块，在换模型族、换任务域时更稳，并且在正确率与计算量之间取得可用的折中。
