§1 · 论文主线

Workflow 级成本–质量分配

在一个甚至多个完整的 agent workflow（每步多 LLM 调用）中，如何利用 workflow 级结构信号（关键步骤、剩余预算、多 WF 共享资源）做整体分配？

当优化单位从「一次 LLM 请求」变成「一个完整 agent workflow」，并且多个 workflow 共享同一预算池和多条后端路径的 RPM / 并发配额时，显式维护 workflow 状态是否会改变固定预算下的最终成功率？ 若肯定，再问：收益来自预算配速、步骤重要性、进展先验，还是多 workflow 调度？把 agent workflow 的 LLM 花费变成一个可审计、可消融、可复现实验的问题。

§2 · 研究问题

三个研究问题

RQ1

多 workflow 在同一固定预算与共享后端限流下并行时，预算浪费在何处？哪些限制最先成为瓶颈？

指标：预算违规率 · 429 率 · 队列延迟 · 回收预算 · 僵尸取消数
RQ2

利用 workflow 阶段状态做多步模型档位选择，是否比「仅按 workflow」或「仅按预算」调度 resolve 更多任务？

指标：固定预算下 resolved rate；BudgetFlow Full vs Workflow-Level Router vs Budget-Only Step Scheduler
RQ3

换模型削弱 prefix-cache 局部性时，workflow 阶段调度是否仍能带来净收益？

指标：换模频率 · prefill 延迟 · cached-token 比例；BudgetFlow Full vs Cache-Sticky

§2 · 独特贡献

五项独特贡献

1

连续质量视角

将 LLM 质量视为 [0,1] 连续变量，而非离散档位。

2

预算硬约束 + 动态配速

budget_factor 近似预算边际价值 λ，硬上限保证不超支。

3

显式任务价值 wᵢ

调用方声明的可解释信号，驱动调度优先级。

4

僵尸止损

截断「成本涨、质量不涨」的无效调用，回收预算与槽位。

5

无需训练

优化启发式，即时部署，对比 RL 方法更轻量。

§5 · 论文边界

Scope · 覆盖与扩展

✅ 本文明确覆盖

  • 单一预算主体：多个并发 workflow 共享一池预算与后端 RPM / 并发配额
  • 决策单位：workflow 内每一步 LLM 调用 + 全局预算池状态
  • 评测：SWE-bench Verified 批量并发 + 固定总预算

🔮 不 Claim / 留作扩展

  • Multi-tenant：跨团队预算与 SLA（自然续作，与 §8 一致）
  • 非 GPU serving 独占：不取代 vLLM / Athena-Serve 侧 KV/batch 最优
  • ZombieDetector：运行时止损构件，可消融；非独立方法论主贡献
  • 成本模型：不绑定具体 SKU；用抽象 $/token 计价即可复现

§7 · 最接近的工作

BoPO: Budget-Aware Agentic Routing

Zhang et al., arXiv:2602.21227, 2026 · Boundary-Guided Policy Optimization

🔗 与本文的关系

BoPO 产出单任务 step 级路由策略，在 BudgetFlow 里对应 ModelSelector 的可插拔实现。本文是运行时治理底座；底座与 BoPO 兼容——可将 RL 策略接入 ModelSelector。

📌 BoPO 明确不覆盖

  • 多 agent 共享全局预算的跨任务分配
  • 生产级 RPM/并发强准入与 429 治理
  • 僵尸任务占用的预算与槽位回收
  • 本地推理/KV 切换代价建模
  • 零域数据下的免训练冷启动路由

§8 · 叙事

参照 vLLM：Single → Multi-Tenant 两阶段

vLLM (SOSP 2023) — 第一阶段处理 single-tenant：一台 GPU 服务器，如何 batch 与调度最大化吞吐？第二阶段（Andes OSDI 2024, SGLang router）扩展到 multi-tenant，做 priority / quota / SLA 仲裁。

本文（Paper 1）· Single-Budget-Owner

一个实体持有固定预算，在其上运行多个 agent workflow。贡献：跨 workflow 分配 cost-model-agnostic scheduler。

续作 · Multi-Tenant

多团队/部门/客户独立预算、优先级与 SLA。新问题：cross-tenant 隔离、quota 仲裁、budget-aware admission control。

scheduler 的 cost-model-agnostic 性质在 multi-tenant 扩展中保留——租户可用不同模型与成本结构，无需修改仲裁层。
