# 017 — PolicyMemory: Real Integration & Warm-up Gate

## What this solves

017 turns PolicyMemory from an island module into an actual, auditable, auto-loading prior system that the runner consumes at runtime. Before 017, PolicyMemory existed as a tested Python class but was never wired into `run_mini_swe_compare.py`. The next run could not benefit from historical data.

## Why 016 PolicyMemory wasn't really integrated

| Gap | Detail |
|-----|--------|
| No import in runner | `run_mini_swe_compare.py` never imported `PolicyMemory` |
| No CLI path | No `--policy-memory` argument; priors couldn't be loaded |
| No `set_task_context` | `AdaptiveRoutingState` was never told which task was starting |
| No trace audit | `routing_prior_summary` was never written to JSONL records |
| Rescue parameters static | `rescue_state_for_strategy()` always returned defaults |

## What 017 adds

### 1. CLI integration

Three new flags on `run_mini_swe_compare.py`:

```
--policy-memory PATH          # JSONL to rebuild priors from
--disable-policy-memory       # Explicitly disable (for cold-start baselines)
--policy-memory-gate-only     # Run gate checks, print summary, exit 0/1
--regret-threshold FLOAT      # Override POLICY_REGRET_THRESHOLD
```

Behavior:
- `--policy-memory data/runs/postfix_017_10x5-0.jsonl` rebuilds priors from that file
- `--resume` + existing output path also rebuilds from the current run's JSONL
- No silent auto-loading — prior path must be explicit
- `--disable-policy-memory` can override even when a path is given

### 2. Warm-up Gate

Before any API call, `--policy-memory-gate-only` runs these checks:

```
policy_memory_loaded = True/False
records_loaded >= 10
repos_loaded >= 1
tasks_loaded >= 10
5 sample task prior summaries
sympy-17630 learned_action != early_rescue (all_pro failures present)
full_vs_tight_regret for each repo
regret_threshold value
Next-run routing impact summary
```

If any check fails → `exit(1)`. No API calls are made.

### 3. Per-task prior application

In `_run_one()`:
```python
adaptive.reset_task_runtime()    # clear prior task state
adaptive.set_task_context(task.instance_id)  # load priors for this task
```

`set_task_context`:
- Computes `routing_prior_summary` from PolicyMemory
- Adjusts rescue parameters (trigger_turns, window_turns, stop_loss_turns) based on `learned_action`
- Stores prior for trace writing

### 4. Trace audit

Every task record now includes:

When policy memory is enabled:
```json
{
  "routing_prior_summary": {
    "repo_t2_success": 0.543,
    "repo_t3_success": 0.533,
    "task_seen": 5,
    "task_all_pro_failures": 0,
    "recent_failure_axis": "repair_fail",
    "full_vs_tight_regret": 0.062,
    "learned_action": "default",
    "regret_threshold": 0.15,
    "policy_memory_source": "data/runs/postfix_017_10x5-0.jsonl"
  },
  "policy_memory_enabled": true
}
```

When disabled: `"policy_memory_enabled": false`

### 5. Regret threshold calibration

Scanned postfix_012, postfix_015, postfix_017 data for full-vs-tight comparisons:

| Source | Repo | Regret | Trigger at 0.15? |
|--------|------|--------|--------------------|
| postfix_012 | django | 0.000 | no |
| postfix_012 | sympy | 0.000 | no |
| postfix_015 | django | 0.105 | no |
| postfix_015 | sympy | 0.348 | **yes** |
| postfix_017 | django | 1.930 | **yes** |
| postfix_017 | sympy | 0.062 | no |

Decision: **keep `POLICY_REGRET_THRESHOLD = 0.15`**

Rationale:
- P75 of positive regret values in postfix_017 (largest dataset) = 0.150
- Catches 2/6 regret signals across all experiments — only clear cases
- Does NOT trigger for marginal regret (0.037–0.079 cluster in postfix_017 sympy tasks)
- Threshold lives in `defaults.py` as `POLICY_REGRET_THRESHOLD` — single source of truth
- Can be overridden via `--regret-threshold` CLI flag

### 6. Compact audit updates

- **T3% denominator**: Now `T3 / (T1+T2+T3)` instead of `T3 / llm_turns`
- **PolicyMemory metadata**: Shows `policy_memory_used`, `policy_memory_source`, `prior_records`
- **T1 turns** now counted in per-strategy breakdown

## How postfix_017 data serves as warm-up prior

1. Load `postfix_017_10x5-0.jsonl` via `--policy-memory`
2. PolicyMemory rebuilds repo/task priors from 50 records (sympy: 9 tasks, django: 1 task)
3. For each task in the next run, `set_task_context` queries the prior
4. Rescue parameters are adjusted per `learned_action`:
   - `cap_t3` for django tasks (full is 2.9x more expensive than tight)
   - `protocol_issue` for sympy-17630, sympy-13647, sympy-16988 (extract_fail common)
   - `default` for the rest (no strong negative signal)
