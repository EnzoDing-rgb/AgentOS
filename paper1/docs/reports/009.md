### Django Analysis

114 Django tasks in test.jsonl. All tested candidates fail with `INSTALLED_APPS` — test models (`tests/<app>/models.py`) not in Django settings. Two known working tasks (django-10924, django-12113) avoid this because their test modules don't import local model classes at module level.

Root cause: `tests/test_sqlite.py` settings file has no `INSTALLED_APPS`. Django's ORM requires app registration for models. Django's own test runner (`tests/runtests.py`) handles this dynamically; our bare-pytest setup does not.

**Decision**: Exclude new Django tasks. Use existing 2 working Django tasks as-is. Focus expansion on SymPy tasks.

## Infrastructure Issues

### Systematic Worktree Crash (budget_only_tight)

All 8 budget_only_tight records (across 008, batch1, batch2) either crash or fail to execute. The pattern:
- Worktree directory already exists from previous runs
- `git worktree add --force` fails on existing directory
- Root cause: budget_only_tight is always the last strategy to run; if any crash leaves a stale worktree, bo_tight fails first on the next run

### Required Fixes Before Further Batches

1. **Worktree resilience**: Add `git worktree remove --force` + `rm -rf` before `git worktree add` in `_prepare_worktree`
2. **resolved=None fix**: Already fixed (line 781 commit)
3. **Auto-budget cap floor for SymPy**: Global fallback `easy=200*2.5=$500` too tight for some tasks — consider raising min_cap or using memory-based estimates earlier
