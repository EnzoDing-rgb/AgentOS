# 026 — Leave-One-Task-Out BudgetMemory Generalization Validation

## 1. Motivation

025 identified that 56/56 rows (021-024 experiments) used `budget_memory_source=exact_task`. This proves plumbing/ledger integration works, but does NOT prove BudgetMemory generalizes — every task had been seen in the warmup JSONL (018).

**Question:** When a task is NOT in the training set, does BudgetMemory produce reasonable budget estimates from repo_median / strategy_median / global_fallback cascade tiers?

## 2. Method: Leave-One-Task-Out (LOO)

### 2.1 Procedure

1. Pool all records from 017, 018, 021, 022, 023, 024 (156 records, 10 unique instance_ids).
2. For each instance_id:
   - Hold out ALL records for that instance_id.
   - Build BudgetMemory from remaining records with `exclude_ids={held_out_id}`.
   - Estimate budget for held-out task.
   - Compare estimated cap vs actual median cost.
3. Zero API calls — pure offline statistical replay.

### 2.2 Anti-overfitting discipline

- **No parameter tuning.** risk_multiplier, task_value, threshold ratios are frozen as-is from the BudgetMemory implementation. No adjusting to make LOO look better.
- **exact_task must be 0%.** The `exclude_ids` parameter in `BudgetMemory.from_jsonl()` ensures the held-out task's records never enter training. Any exact_task match in LOO results indicates a bug.
- **Distinguish warm-start from generalization.** exact_task lookups are the warm-start baseline (working as designed for seen tasks). LOO tests the cascade tiers: repo_median → strategy_median → global_fallback.

## 5. Cascade Tier Analysis

### Why repo_median dominates (90%)

The dataset has 10 tasks from 2 repos:
- sympy: 9 tasks, 138 records → repo median is well-populated, hits the >= 3 threshold easily
- django: 1 task, 18 records → falls through to strategy_median (>= 2 records for strategy)

This distribution is an artifact of SWE-bench Mini's task composition. The repo_median tier works well for repos with multiple tasks; for single-task repos, strategy_median provides a reasonable fallback.

### What would trigger global_fallback

`global_fallback` would trigger if:
1. Exact task not in training (guaranteed by exclude_ids in LOO)
2. Repo has < 3 records in training
3. Strategy has < 2 records in training

This cascade hasn't been tested because:
- No cross-dataset LOO (e.g., train on SWE-bench, test on SWE-bench-Lite)
- No unseen-repo stress test (all 10 tasks are from known repos)

## 6. Limitations

1. **10 tasks, 2 repos.** LOO tests repo_median for sympy (well-populated) but only strategy_median for django (1 task). The full cascade (repo_median → strategy_median → global_fallback) hasn't been exercised with a truly unseen repo.

2. **No cross-dataset test.** All tasks appear in the same dataset distribution. Cross-dataset transfer (train on one benchmark, estimate on another) would stress-test the higher cascade tiers.

3. **sympy__sympy-20212 is severe_underbudget.** The single severe failure is a genuinely hard task. The repo_median estimate ($0.14) is derived from sympy tasks that are mostly easier. This is a fundamental limitation of repo-level statistics — outlier tasks within a repo get poorly estimated.

4. **risk_multiplier is conservative.** All estimates use 1.4x risk (1.0 + 0.20 * 2.0, where budget_exhaustion_rate ≈ 20% for sympy). This might be too low for hard tasks.

## 7. Decision: Run 027?

**Gate A passed.** BudgetMemory LOO generalization is adequate.

**Pre-conditions for 027 (5×2):**
1. Gate B infra checks pass (checker on 025/026 artifacts, no orphans)
2. `--budget-memory-exclude-ids` flag verified working
3. `--jobs 1` to avoid worktree deadlock
4. 5 tasks × 2 strategies = 10 runs (small enough to complete in < 1 hour)

**027 experiment design:**
- 5 tasks: select from 10 with diversity across repos and difficulty
- 2 strategies: `budget_only_tight` vs `budgetflow_full_tight`
- `--budget-memory data/runs/postfix_017_10x5-0.jsonl,...` with `--budget-memory-exclude-ids <027-task-ids>`
- This ensures BudgetMemory estimates come from repo_median/strategy_median — NOT exact_task

**Post-027 evaluation:** Focus on source distribution, not just pass count. The key metric is whether `budget_memory_source != exact_task` AND the estimates produce reasonable caps.
