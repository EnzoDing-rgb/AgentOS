## (a) Why 011→015 Score Drop?

The "drop" from 22/25 (012/postfix_011_sanity) to 12/25 (015/postfix_012_trace_sanity) has a clear cause:

**012 had a bug that made BudgetFlow degenerate to all_pro + overhead.**

The routing formula in 012 had `PROGRESS_SCALE=18.0` with an inverted comparison (`score >= pressure` → always true). This made every backend selection pick T3 (GPT-5.4). So `budgetflow_full_*` was effectively identical to `all_pro` — all strategies used the strongest model on every turn.

015 fixed the formula (`PROGRESS_SCALE=0.3`, `pressure >= upgrade_threshold`). Now BudgetFlow genuinely routes to T2 (~80% of turns) and escalates to T3 only when justified. The pass rate dropped because T2 is genuinely less capable than T3 — the "drop" exposes the real capability gap that the bug was hiding.

**Breakdown:**

| Experiment | all_pro | bf_tight | bf_loose | bo_tight | bo_loose | Note |
|-----------|---------|----------|----------|----------|----------|------|
| 012 (bug: 100% T3) | 5/5 | 5/5 | 5/5 | 3/5 | 4/5 | bf ≈ all_pro |
| 015 (fixed: 80% T2) | 3/5 | 2/5 | 3/5 | 2/5 | 2/5 | real T2 vs T3 gap |
| 016 (fixed + cap/bo fixes) | 4/5 | **5/5** | 4/5 | 3/5 | 3/5 | routing fix + cap relax |

The 2 ceiling-looking tasks (sympy-18189, sympy-18057) were actually model non-determinism, not true ceilings — see (b).

## (d) Bugs Fixed

### 1. budget_only T3 window unreachable (policies.py)

**Root cause:** `BudgetOnlyStepRouter.choose_backend()` checked `n >= 3` for the T3 window, but the active pool is [T2, T3] (T1 skipped), so `n == 2`. The `n == 2` branch hard-returned `ordered[0]` (T2) without checking pressure.

**Fix:** Added T3 path in the `n == 2` branch when `budget_pressure < 0.15`. Mirrors the existing `n >= 3` T3 window.

**Impact:** bo_loose T3 usage went from 0% → 45%. bo_tight from 0% → 19%.

### 2. bf_full T2 cap blocking legitimate T3 (strategies.py)

**Root cause:** `_budgetflow_max_tier()` only allowed T3 if `last_backend.tier >= 3` (already escalated). The fixed selector formula already prefers T2 at low pressure, but the cap blocked T3 even when the selector's upgrade threshold was crossed.

**Fix:** Added pressure-based gate: when `budget_pressure >= 0.15`, lift the T2 cap. The selector's upgrade_threshold (e.g., ~0.46 for T2→T3 REPAIR) still gates actual T3 selection — the cap just stops being an artificial ceiling.

**Impact:** bf_tight went from 2/5 → 5/5 PASS.

### 3. gold_rescue_stop_loss misleading exit reason (mini_swe_proxy.py)

**Root cause:** When rescue detects gold was edited but evidence has accumulated for stop_loss_turns without resolution, it stops and evaluates the worktree patch. The exit reason was `"gold_rescue_stop_loss"` — implying failure even when the harness finds the patch works (PASS).

**Fix:** Renamed to `"rescue_timeout_gold_edited"`. Accurately describes: rescue timed out after gold was edited, worktree patch is being evaluated. Updated `failure_classification.py` to match.

**Impact:** No behavioral change. Observability fix — exit reason now accurately reflects mechanism.
