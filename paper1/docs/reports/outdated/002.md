## P2P 失败症状

```
FAILED sympy/printing/tests/test_latex.py::test_latex_Float
AssertionError: assert 'inf' == '\\infty'
    latex(1.0*oo) == r"\infty"  →  got 'inf'
```

模型 patch 只改了 `sympy/printing/latex.py` 第 740 行的 `inv_trig_table`:

```diff
-inv_trig_table = ["asin", "acos", "atan", "acot"]
+inv_trig_table = ["asin", "acos", "atan", "acsc", "asec", "acot"]
```

这个改动与 `latex(1.0*oo)` 的渲染 **完全无关**。

## 调查结果

### 每个问题的答案

**1. 干净 base commit + test_patch，不应用 model_patch，PASS_TO_PASS 是否本来就失败？**

**是的。** 在干净 base commit (8fc63c2d71) 上，撤销 model patch 后：

```
$ python3 -c "from sympy import oo, latex; print(repr(latex(1.0*oo)))"
'inf'
```

```
$ python3 -m pytest sympy/printing/tests/test_latex.py::test_latex_Float -x
FAILED - AssertionError: assert 'inf' == '\\infty'
```

`test_latex_Float` 在 **完全没有应用 model patch** 的情况下就失败。

**2. base commit + test_patch + model_patch，是否只有 P2P 失败？**

是的。Harness verdict:
```
test_patch=ok, fail_before=fail, model_patch=ok, fail_after=pass, pass_to_pass=fail
```
- test_patch 正确应用
- fail_before 正确失败（原测试捕捉到 bug）
- model_patch 正确应用
- fail_after 正确通过（model patch 修了 bug）
- 只有 pass_to_pass 失败，且是 `test_latex_Float::latex(1.0*oo)` 一个测试

**3. `latex(1.0*oo)` 输出 `inf` 在 base 环境是否存在？**

**存在。** 这是 mpmath 版本不兼容问题，不是模型引入的问题。

**4. Harness 顺序是否正确？**

是的。`local_harness.py::evaluate_local_harness` 的顺序（行 450-514）：
1. `apply_patch(test_patch)` → test_patch_ok ✓
2. `run_pytest(fail_to_pass)` → fail_before ✓
3. `apply_patch(model_patch)` → model_patch_ok ✓
4. `run_pytest(fail_to_pass)` → fail_after ✓
5. `run_pytest(pass_to_pass)` → pass_to_pass ✓

顺序正确，无 bug。

**5. Python 版本 / dependency 和官方 SWE-bench 是否一致？**

**不一致。**
- 当前: Python 3.12.3, mpmath 1.4.1, SymPy 1.1.2.dev
- 官方 SWE-bench: Python 3.10（通过 Docker 容器），mpmath 版本较旧（与 sympy 1.1.2.dev 兼容）

`python_compat` 只修 `collections.X` → `collections.abc.X`，不修 mpmath。

**6. P2P 失败是否来自环境兼容？**

**是的。** 根本原因：

`sympy/printing/latex.py::_print_Float`（行 358-361）：
```python
elif str_real == "+inf":
    return r"\infty"
elif str_real == "-inf":
    return r"- \infty"
else:
    return str_real
```

`mlib.to_str(expr._mpf_, dps, strip_zeros=True)` 调用链：
- sympy 调用 `mlib.to_str(mpf_tuple, dps, strip_zeros=True)`
- mpmath 1.4.1 没有顶层 `to_str` 函数
- sympy 回退到 `mpmath.libmp.to_str()`
- `mpmath.libmp.to_str((0, 0, -456, -2), dps)` 返回 `'inf'`（**不带 `+` 号**）
- 旧版 mpmath 返回 `'+inf'`（带 `+` 号）
- 因为 `'inf' != '+inf'`，条件不匹配，fall through 到 `return 'inf'`
- 测试期望 `'\\infty'`

证据命令：
```
$ python3 -c "
from mpmath.libmp import to_str
print(repr(to_str((0, 0, -456, -2), 15, strip_zeros=True)))
"
'inf'
```

## 影响范围

这个 bug 影响 **所有 sympy__sympy-14774 的 P2P 测试**，不管用什么策略（all_pro, budget_only, budgetflow_full），只要用本地 harness 跑 P2P，`test_latex_Float` 就会失败。

之前 `clean_gold2-0` 中 `all_t1_tight sympy__sympy-14774` 的 `loc_fail` 和 `budget_only_tight sympy__sympy-14774` 的 `repair_fail` 也可能被 P2P 污染——如果模型 patch 本身没问题，但 P2P 假失败会导致 `harness_resolved=False`。

**推荐：暂停所有实验，直到 harness 修好。**

## 修复建议

### 修复 A：锁定 mpmath 版本（推荐）

在 harness 的 pip install 步骤中，锁定 mpmath 到旧版本（如 1.1.0 或 1.2.1），使 `to_str` 返回 `'+inf'` 而不是 `'inf'`。

需要验证：旧版 mpmath 是否与 Python 3.12 兼容。

### 修复 B：在 apply_python_compat 中修补 _print_Float（临时）

在 `local_harness.py::_patch_python_compat_text` 之后，加入对 `sympy/printing/latex.py::_print_Float` 的 monkey-patch，将：
```python
elif str_real == "+inf":
    return r"\infty"
```
改为：
```python
elif str_real in ("+inf", "inf"):
    return r"\infty"
```

这是最小侵入式的修复，但治标不治本。

### 修复 C：使用 Docker harness（长期）

切换到 official SWE-bench Docker evaluation，确保环境一致性。local harness 仅用于快速开发/诊断。
