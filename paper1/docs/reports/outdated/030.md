# 030 — 10x2 Cold-Start Fallback Test（非 LOO Generalization）

## 1. 实验语义修正

030 使用 `--budget-memory-exclude-ids` 排除了全部 10 个 task。训练集（017/018/021-024）的记录全部属于这 10 个 task，因此：

- 排除后训练集大小 = **0 records, 0 tasks, 0 repos**
- BudgetMemory 4-tier cascade 全部落空，全部走 `global_fallback: no data, default $0.50`
- 所有 task cap = `$0.50 × risk=3.0` = **$1.50**

**结论：030 不是 LOO generalization 实验，是 cold-start no-history fallback test。**

## 3. 对论文 Claim 的影响

**030 只能证明：BudgetMemory fallback 在 cold-start 下能跑，不会崩。**

**不能证明：**
- BudgetMemory 泛化能力（训练数据为空，没东西可以泛化）
- BudgetFlow 在 cold-start 有优势（双方打平，bf 更贵）
- adaptive pressure model 需要 prior（没 prior 时 bf 过度调用 T2，235 vs 93 calls）

**一句话：030 是 fallback safety test，不是 generalization test。LOO generalization 需要保留 N-1 个 task 的训练数据，对应 029 的 5-task LOO 设计。**

## 4. 下一步实验建议

**不推荐直接跳到 15/20 task。** 当前需要先确认基础机制正确。

### 候选 A：Rerun 5x2 LOO with confirmed normalization

```
--ids <5 held-out tasks> --strategies budget_only_tight,budgetflow_full_tight
--budget-memory <017-024> --budget-memory-exclude-ids <same 5 tasks>
```

验证 028 的 `normalize_repo_key()` fix 在真实实验中命中 `repo_median`（029 已验证通过）。重跑确认结果可复现，给论文提供 "LOO with repo_median works" 的干净证据。

### 候选 B：More seeds/repeats 测方差

```
--ids <10 tasks> --strategies budget_only_tight,budgetflow_full_tight
--preset 10x3  # 3 repeats
```

不排除训练数据（完整 BM），测 bo/bf 在 3+ seed 下的方差，确认 023/024 的结果是否稳定。

### 推荐：A

**理由：**
- A 验证核心机制（repo_median cascade fix），论文 claim 依赖这个
- B 是规模实验，应在机制确认后再做
- 030 反直觉结果（双方打平）恰恰说明需要先回到有训练数据的场景确认基础行为正确
- 029 只跑了一次，需要 second seed 确认 repo_median 结果可复现
