### A.5 Remaining Boundaries

1. **goal-loop requires `state.json` via `create_workflow()`** — manually created
   prompt files without `state.json` are invisible to `_find_next_issue()`. The
   `create_workflow()` API initializes state, prompt, and placeholder files in
   one call. This is working as designed but worth documenting.
2. **No real API validation in Phase M** — this phase uses fake-worker dispatch
   only. Real API path was validated in Phase L (042) and is unchanged.
3. **Dispatch wrapper hardening** could support per-issue environment variables
   or model overrides, but the current marker-based design is sufficient for
   the two-profile (fake/API) use case.
