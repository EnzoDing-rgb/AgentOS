## Step 2: Auto-budget v1 Improvements

### New Heuristics

| Parameter | v0 (007) | v1 (008) |
|-----------|---------|---------|
| Scale | 1.5 | 2.5 |
| Min cap | 120 | 200 |
| Max cap | 3000 | 3000 |
| Django floor | none | $600 estimated_cost |
| Estimation priority | history → fallback | memory_exact → memory_exact_any → history_exact → memory_repo_knn → global_fallback |

### Continuous Learning Memory

Added `AutoBudgetMemory` class:
- Reads/writes JSONL records per run
- Each record captures: features, strategy, outcome, cost, cap, cap_sufficiency signal
- `build_record()` factory produces standardized records
- `_classify_cap_sufficiency()`: 6 states — `sufficient`, `likely_underbudget`, `underbudget_or_model`, `not_enough_evidence`, `exclude_harness`, `exclude_corrupt`

### Cap Formula

```
estimated_cost = max(repo_floor, estimated_cost)
cap = clamp(max(repo_floor, min_cap, estimated_cost * scale), min_cap, max_cap)
```

Django floor: `_REPO_FLOOR_ESTIMATED_COST = {"django/django": 600.0}` ensures Django tasks get at least $600 * 2.5 = $1500 cap.

### Underbudget Inflation

When memory records show `likely_underbudget`, estimated_cost is inflated to `max(underbudget_cost) * 1.5` to prevent repeated underbudgeting.
