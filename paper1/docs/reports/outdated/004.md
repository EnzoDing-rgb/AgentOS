## Bugs Fixed

### Bug A: SymPy mpmath compat (002.md P2P false negative)

**Phenomenon:** `sympy__sympy-14774` P2P failed on `test_latex_Float` even on clean base commit. `latex(1.0*oo)` returned `'inf'`, test expected `'\infty'`.

**Root cause:** mpmath 1.4.1 `libmp.to_str()` returns `'inf'` (no `+` sign). Old SymPy `_print_Float` only checks `str_real == "+inf"`.

**Fix:** `SymPyHAdapter.apply_compat()` patches `sympy/printing/latex.py` to use `str_real in ("+inf", "inf")` instead of `str_real == "+inf"`. Applied as direct file modification during harness eval. Does not leak to agent worktree (harness and agent use separate worktrees).

### Bug B: Django test name mapping

**Phenomenon:** Django gold patches failed with `no pytest node ids`. SWE-bench Django test names use format `test_name (module.ClassName)` — no file path prefix.

**Root cause:** `build_pytest_node_ids` couldn't map `test_custom_test_name (backends.sqlite.test_creation.TestDbSignatureTests)` to a pytest node id. Plain `def test_custom_test_name (` search failed because the function name was embedded in a longer string.

**Fix:** `DjangoHAdapter.map_test_name()` parses the parenthesized format, extracts module path and class name, constructs `tests/{module/to/path}.py::ClassName::test_name`.

### Bug C: Django environment not configured

**Phenomenon:** After test name mapping fix, pytest errored with `ImproperlyConfigured: Requested setting DATABASES, but settings are not configured`.

**Root cause:** Django tests import Django modules that access settings, but `DJANGO_SETTINGS_MODULE` was not set.

**Fix:** `DjangoHAdapter.pytest_env()` returns `{"DJANGO_SETTINGS_MODULE": "tests.test_sqlite"}`. `run_pytest()` merges adapter env vars into subprocess env.

## Architecture: RepoHarnessAdapter

```
RepoHarnessAdapter (base)
  ├── apply_compat(repo_dir) → list[str]   # file-level compat fixes
  ├── map_test_name(raw) → str | None       # SWE-bench → pytest node id
  ├── pytest_env() → dict[str, str]         # extra env vars for pytest
  └── for_task(task) → adapter              # factory dispatch

SymPyHAdapter    — infinity patch for _print_Float
DjangoHAdapter   — test name mapping + DJANGO_SETTINGS_MODULE
RequestsHAdapter — placeholder (no compat needed yet)
DefaultHAdapter  — no-op
```

## Design Decisions

1. **Direct file modification, not git patch.** Compat changes use string replacement like `apply_python_compat`. Git patches are line-number sensitive across commits. Direct replacement is robust.

2. **Adapter per repo, not per task.** Single adapter instance covers all tasks in a repo. No per-task state.

3. **Env vars through adapter, not hardcoded.** `pytest_env()` keeps repo-specific env in one place. `run_pytest` merges without knowing repo details.

4. **Resolved index tracking.** `build_pytest_node_ids` tracks which raw names were already mapped by adapter, skips them in the plain-name scan. Prevents double-processing.

## Remaining Known Issues

- Django 10924 and 12113 pass with `tests.test_sqlite` settings (SQLite backend). This works for the specific tests in these tasks (model_fields, backends/sqlite). Django tasks that need PostgreSQL/MySQL would need different settings modules.
- `RequestsHAdapter` is a placeholder. Gold probe on requests tasks would likely need its own compat (Python 3.12 `cgi` deprecation, etc.).
- `apply_python_compat` (collections ABC) remains separate from adapter. Could be folded into adapter later, but not needed now.
