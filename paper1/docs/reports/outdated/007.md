## 2. What Was Implemented

### 2.1 `auto_budget.py` 模块

核心组件：

- **`_HISTORICAL_PRIOR`**：嵌入式历史先验，6 个 sympy 任务的 median_cost + resolved/total + dominant_tier。来源：`docs/reports/historical_budgeting_prior.md`（源 JSONL 文件在 HPC 不可用）。
- **`BudgetEstimate`** dataclass：`instance_id`, `estimated_cost`, `cap`, `source`, `confidence`, `features`
- **`AutoBudgetEstimator`**：两步估算逻辑：
  1. **Exact history match**：查 `_HISTORICAL_PRIOR`，用 `median_cost × scale` → clamped cap。confidence = high（resolved≥3 且 ratio≥0.75）或 medium。
  2. **Fallback**：`difficulty_score = patch_lines + f2p_count × 2` → bucket（easy/medium/hard）→ `_FALLBACK_COST[bucket] × scale` → clamped cap。confidence = low。
- **`from_history(path)`** class method：从 JSONL 加载历史记录，按 instance_id 分组计算 median。文件不存在或为空时 fallback 到嵌入式 prior。
- **`_clamp(value, lo, hi)`**：helper。

## 3. Experiment Spec

### Command

```bash
cd paper1 && PYTHONPATH=src:../external/mini-swe-agent/src \
../.venv/bin/python -u -m budgetflow.run_mini_swe_compare \
  --no-provider-signature-check \
  --ids sympy__sympy-14774,django__django-12113,django__django-10924 \
  --strategies all_pro,budget_only_tight,budgetflow_full_tight \
  --auto-budget --auto-budget-scale 1.5 --auto-budget-min 120 --auto-budget-max 3000 \
  --jobs 3 --step-limit 80 --heartbeat 30 \
  --trace-turns --trace-max-turns 80 \
  --run-series auto_budget_v0_007
```

### Auto-Budget Estimates

```
sympy__sympy-14774 est=42.2 cap=120.0 source=history_exact confidence=high
django__django-12113 est=200.0 cap=300.0 source=fallback confidence=low
django__django-10924 est=200.0 cap=300.0 source=fallback confidence=low
```

- sympy-14774：历史 7/7 resolved，median_cost=42.2 → cap=$120（clamped to min）
- django 任务：无历史数据 → fallback easy bucket（patch≈10-12 lines, f2p=1）→ cap=$300

### 设计决策

| 参数 | 值 | 理由 |
|---|---|---|
| `--auto-budget-scale` | 1.5 | 给 historical median 留 50% 余量 |
| `--auto-budget-min` | 120 | 确保即使极简单的任务也有足够预算跑完一轮 |
| `--auto-budget-max` | 3000 | 防止极端 outliers 无限消耗 |
| `--auto-budget-mode` | per_task | 每任务独立 cap，避免共享池饥饿 |

## 5. Interpretation

### 5.1 Auto-Budget 效果

**共享池饥饿已解决。** 006 中 `--tight 250` 是共享池，sympy 任务内部 T2→T3 escalation 消耗全部 $250，django 任务 cost=0 无法运行。007 中每任务独立 cap（来自 auto-budget estimator），django 任务全部获得 $300 预算并实际运行了 10-14 turns。

**但 qwen3-coder-plus 无法解决 django 任务。** 这不是预算问题，是模型能力问题。budget_only_tight 和 budgetflow_full_tight 在 django 上全部 NO PATCH（没找到 gold file）。只有 GPT-5.4 (all_pro) 能定位并编辑 django gold file。

### 5.2 模型表现

| 模型 | 策略 | 结果 |
|---|---|---|
| GPT-5.4 | all_pro | 2/3 PASS（django-12113 repair_quality 失败是真实模型限制） |
| qwen3-coder-plus | budget_only_tight | 1/2（sympy PASS, django FAIL） |
| qwen3-coder-plus + GPT-5.4 | budgetflow_full_tight | 0/3（全部 NO PATCH） |

budgetflow_full_tight 的 0/3 值得注意：即使是混合 routing（T2 起 + T3 escalation），3 个任务全部在预算耗尽前没找到 gold file。sympy-14774 在 006 中 budgetflow_full_tight 是从 worktree fallback 提取 patch 才 PASS 的；007 中 cap=$120 可能太紧使得 worktree 没来得及产生有意义的 diff。

### 5.3 Harness 可信度

3 条 PASS 全部 harness 阶段正常。1 条 repair_quality FAIL（django-12113 × all_pro）harness 细节显示 `model_patch=error: corrupt patch`，说明模型生成了有问题的 patch，不是 harness 误判。**无 false positive/negative。**

### 5.4 Worktree Crash

django-10924 × budget_only_tight 因 `git worktree add --force` 在残留目录上失败（exit code 128）。这是已知 edge case（006 Section 7.4），不是 auto-budget 引入的问题。清理命令：
```bash
cd paper1/data/repo_cache/worktrees && git worktree prune
```

### 5.5 Estimator Calibration

| 任务 | cap | 实际 cost | 利用率 |
|---|---|---|---|
| sympy-14774 budget_only | $120 | $120 | 100% |
| sympy-14774 all_pro | $120 | $96.2 | 80% |
| django-12113 budget_only | $300 | $300 | 100% |
| django-12113 budgetflow_full | $300 | $300 | 100% |
| django-10924 budgetflow_full | $300 | $293.3 | 98% |
| django-10924 all_pro | $300 | $293.8 | 98% |

- sympy-14774：$120 cap 刚好够 budget_only（9 turns），但对 budgetflow_full 偏紧（NO PATCH）。建议 scale=2.0 或 min_cap=200 给 routing workflow 更多空间。
- django 任务：$300 cap 被完全利用（~293-300），但 qwen3-coder-plus 仍然找不到 gold file。可能需要更高 cap（更长的探索）或更好的模型。

## 6. Risks / Unknowns

| Risk | Detail |
|---|---|
| Fallback 先验弱 | django 任务无历史数据 → fallback heuristic（patch_lines + f2p_count）。实际 SWE-bench 任务难度不完全由这两个特征决定 |
| 嵌入式 prior 范围窄 | 只有 6 个 sympy 任务。扩展到其他 repo 时需要更多历史数据 |
| Worktree crash | 同 006 edge case，需要 run 前 `git worktree prune` 或在代码中自动清理 |
| Budget 策略 0/3 django | qwen3-coder-plus 在 django 上完全无法定位 gold file。可能需要 T2 直接配 adapter 或提高 routing 的 T3 比例 |
| budgetflow_full_tight 0/3 | $120 sympy cap + $300 django cap 对 full routing workflow 可能偏紧。需要更高 scale |

## 7. Recommended Next Step

**分析 routing 行为，而非继续校准预算。** auto-budget 已经证明能防止共享池饥饿（django 任务从 $0 → $300），但 budget 策略的 0/3 结果说明是模型能力或 routing 逻辑的问题，不是预算分配问题。

最小动作：
1. 用已有 trace 数据分析 budgetflow_full_tight 为什么找不到 gold file（LOC 阶段走了多少步？T3 什么时候升级的？）
2. `git worktree prune` 清理残留
3. 考虑是否需要 T2 直接配 adapter（类似 `local_harness.py` 的 compat 逻辑）
4. 如果要跑下一轮：`--auto-budget-scale 2.0 --auto-budget-min 200` 给 routing workflow 更多呼吸空间
5. 不建议现在扩任务集。先理解 3×3 的 routing 细节。
