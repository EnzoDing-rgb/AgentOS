## Phase J-fix Review

Phase J initial delivery had semantic errors in the 040 artifacts: the goal
was marked "complete" despite containing FAIL (issue-a, fake worker no
metadata) and WARN (issue-b, false positive) reviews. The review gate itself
lacked invariants to prevent this. Phase J-fix resolved all issues.

### Issues Found (Phase J initial)

1. **Goal complete with FAIL review** — Issue 040-issue-a had no
   `worker_metadata.json` (fake worker), so the deterministic review gate
   returned FAIL. The goal was still marked "complete." This violates the
   invariant that a goal with any FAIL review cannot be complete.

2. **Goal complete with WARN review** — Issue 040-issue-b triggered a false
   positive on "zero-cost fake worker" — the factual error heuristic flagged
   "zero-cost" without checking whether the phrase described the fake worker
   (accurate) vs. the thin API worker (inaccurate).

3. **mark-complete bypassed review gate** — `mark-complete` did not check
   `codex_review.md` before marking a workflow complete. FAIL and WARN reviews
   could be ignored.

4. **goal-review exit codes undifferentiated** — FAIL and WARN both returned
   exit code 1; only all-PASS returned 0. WARN should return 2 to distinguish
   it from FAIL.

### Fixes Applied

1. **Goal completion invariant** (`autoresearch_goal.py`):
   - Added `_check_goal_reviews()`: scans all `codex_review.md` files,
     returns 'pass' / 'warn' / 'fail'
   - `run_goal()` before setting status to "complete": checks reviews first.
     FAIL → goal status "failed"; WARN → goal status "review_required";
     only all-PASS → "complete"

2. **mark-complete enforcement** (`run_autoresearch.py`):
   - Checks `codex_review.md` before allowing mark-complete
   - FAIL → rejected (exit 1)
   - WARN → requires `--owner-override REASON`; override recorded in
     `final.md`
   - PASS → allowed

3. **goal-review exit codes** (`run_autoresearch.py`):
   - FAIL → exit 1
   - WARN → exit 2
   - all PASS → exit 0

4. **Fake worker auto-detect** (`autoresearch_codex_gate.py`):
   - If output contains `AUTORESEARCH_FAKE_WORKER_RESULT:PASS`, applies
     fake-worker profile: checks marker presence, required sections, no
     secrets — does NOT require `worker_metadata.json`

5. **Factual error heuristic fix** (`autoresearch_codex_gate.py`):
   - `_check_factual_errors()` now checks context: if "fake worker" appears
     within 80 chars of a "zero cost" claim, skips the match (describing
     the fake worker as zero-cost is accurate)

6. **Marker appended forces WARN** (`autoresearch_codex_gate.py`):
   - Check 4 (`marker_appended_by_wrapper`) now forces minimum WARN verdict
     even if score >= 80, since an appended marker means the model output
     was incomplete

## Task A: Fix Phase I Evidence Inconsistencies

### Issues Found

1. **summary.md status ≠ JSON status** — 039 summary showed `Status: running`
   while goal JSON had `status: complete`. Root cause: `write_goal_summary()`
   used the in-memory Goal object's status without re-reading from disk.

2. **total_api_calls = 0** — Never incremented because `GoalManager.run_goal()`
   doesn't know whether the worker made a real API call. The field was always
   stale.

3. **write_goal_summary() used stale data** — Read `goal.total_api_calls` from
   the in-memory object, which was always 0 on first load from disk.

### Fixes

**New method `_aggregate_goal_metadata()`** in `autoresearch_goal.py`:
- Scans all workflow directories for the goal's issues
- Finds each issue's latest attempt's `worker_metadata.json`
- Aggregates: `total_api_calls`, `total_input_tokens`, `total_output_tokens`,
  `marker_appended_count`, `successful_http_calls`
- Only counts the latest attempt per issue

**Updated `write_goal_summary()`**:
- Calls `_aggregate_goal_metadata()` on every invocation
- Writes aggregated facts back to goal JSON (fixes `total_api_calls`)
- Includes token counts and evidence metrics in the summary

## Task B: PASS Marker Evidence Hardening

### Changes to `scripts/autoresearch_api_worker.py`

**Strict default behavior:**
- Model output lacking `AUTORESEARCH_REAL_API_SMOKE:PASS` → exit code 1
- `marker_present_in_model_output` = false in metadata
- `marker_appended_by_wrapper` = false (no forgery)
- Output still written to disk for inspection

**`--allow-wrapper-marker` flag:**
- Explicit opt-in for backward compatibility
- When set: appends PASS marker as before, exits 0
- Used only when the caller explicitly accepts wrapper-appended markers

**Arg parsing refactored:** `--allow-wrapper-marker` parsed before positional
args; positional args extracted via `[a for a in argv[1:] if not a.startswith("--")]`.

## Task C: Deterministic Codex Gate

### New module: `src/budgetflow/autoresearch_codex_gate.py`

**Core function: `review_issue(workflow_dir) -> ReviewResult`**

Reads `state.json`, latest `worker_output.md`, and `worker_metadata.json`.
Runs 7 deterministic checks:

| # | Check | Weight | What it verifies |
|---|-------|--------|------------------|
| 1 | http_status_200 | 40 pts | API call succeeded |
| 2 | tokens_positive | 20 pts | input/output tokens > 0 |
| 3 | marker_present_in_model_output | 30 pts | Model output contains PASS marker |
| 4 | marker_not_appended_by_wrapper | 20 pts | Wrapper didn't forge the marker |
| 5 | factual_header_consistent | 15 pts | Output header matches metadata |
| 6 | no_secrets_leaked | 100 pts (auto-fail) | No API keys in output or metadata |
| 7 | factual_accuracy | 10 pts (warn) | Heuristic factual error detection |

**Factual error detection** — 5 regex patterns catch:
- "zero API cost" / "zero-cost" — when tokens were actually consumed
- "costs nothing" — same
- "no cost" — same
- "without API calls" — when metadata shows API usage
- "completely/totally free" — same

All patterns only fire when `input_tokens > 0`.

**Scoring:**
- Start at 100, deduct per failure
- < 60 → FAIL, < 80 → WARN, >= 80 → PASS (if no warnings)
- Secret leak → automatic 0

**Output format** — `write_codex_review()` produces:
```markdown
# Codex Gate Review — <issue_id>
## Verdict
VERDICT: PASS|WARN|FAIL
SCORE: N/100
## Evidence
## Warnings
## Checks
| Check | Result | Detail |
## Next Action
AUTORESEARCH_RESULT:PASS|WARN|FAIL
```

|---------|---------|
| `review --issue-id ID` | Deterministic review of one issue |
| `goal-review --goal-id ID` | Review all issues in a goal + write summary |

## Remaining Gaps

1. **Codex automatic review** — `codex_review_fn` callback exists but review
   is either manual or deterministic-local. Using the thin API worker as an
   LLM reviewer is the next step.

2. **Post-gate auto commit/push** — After Codex approves an issue, accepted
   changes should be committed and pushed automatically.

3. **Owner approval resume UX** — No `goal-resume` command yet. When a Goal
   pauses or enters `review_required`, the owner must manually override.

4. **Goal dependency ordering** — Issues run sequentially; no support for
   "B depends on A" or parallel execution.

5. **CLI usability** — `goal-review` re-runs reviews fresh each time.
   A `goal-review --cached` mode that reads existing `codex_review.md`
   files without re-evaluating would be faster for status checks.
