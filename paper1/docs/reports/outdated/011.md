## Bug Found & Fixed: `.1f` Cost Display

### Root Cause

All cost/cap display lines in `run_mini_swe_compare.py` used `.1f` formatting, designed when internal cost units were in the 100-30,000 range. After real USD calibration, costs are in the $0.01-$10 range.

| Actual value | `.1f` display | Information lost |
|---|---|---|
| $0.01 | `0.0` | **100%** |
| $0.05 | `0.0` or `0.1` | **0-100%** |
| $0.25 | `0.2` or `0.3` | **±20%** |
| $1.50 | `1.5` | acceptable |
| $10.00 | `10.0` | acceptable |

This means **all post-010 real-run printouts would show sub-dollar costs as `0.0`**, making it impossible to distinguish a $0.01 T1 task from a $0.05 T2 task.

### Fix

Added `_fmt_usd()` adaptive formatter in `run_mini_swe_compare.py`:

| Range | Format | Example |
|---|---|---|
| `0` | `"0"` | 0 |
| `< $0.01` | `.6f` | 0.005 → `0.005000` |
| `< $1.00` | `.4f` | 0.05 → `0.0500` |
| `≥ $1.00` | `.2f` | 1.50 → `1.50` |
| `None` | `"uncapped"` | — |

Applied to all 15 cost/cap display points across the file.
