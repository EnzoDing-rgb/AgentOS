### 2.1 Worktree "missing but locked" fix (`local_harness.py`)

**`_remove_worktree` 重写为 5 层清理：**

1. `git worktree unlock` — 先解锁（挂锁会阻止 prune 和 re-add）
2. `git worktree remove --force` — 如果目录还在
3. `shutil.rmtree(meta_dir)` — 删除 `.git/worktrees/<name>` 元数据（解决 "missing but locked"）
4. `shutil.rmtree(worktree_path)` — 文件系统清理，无视 git 状态
5. `git worktree prune` — 清理残留引用

**`_worktree_add` 新增 retry 逻辑：**

- `git worktree add` 失败后解析 stderr
- `"invalid reference"` → re-fetch commit + retry
- `"missing but locked"` / `"locked worktree"` → unlock + nuke meta_dir + prune + retry
- 其他错误 → `check_returncode()` 抛出

之前添加 worktree 前只调了 `_remove_worktree`，但没有处理 remove 本身 clean 但 add 仍报 locked 的竞态（并行 job 可能在不同 main repo lock 窗口内创建了同名 worktree 元数据）。

### 2.2 Checkpoint `batch_cap: null` (`compare_checkpoint.py`)

`StrategyCheckpoint.from_dict` 遇到 `batch_cap: null` 时 `float(None)` 抛出 TypeError，导致 resume 崩溃。修复：

```python
# from_dict
raw_cap = data.get("batch_cap")
if raw_cap is None:

# to_dict — always write a number
"batch_cap": self.batch_cap if self.batch_cap is not None else 0.0,
```

## BudgetFlow Routing 分析

**关键发现：BudgetFlow Full 路由 100% 到 T3（GPT-5.4），budget_only 路由 100% 到 T2（qwen3-coder-plus）。**

| strategy | T1 | T2 | T3 | 解释 |
|---|---|---|---|---|
| all_pro | 0% | 0% | 100% | 固定 T3 |
| budgetflow_full_tight | 0% | 0% | 100% | BudgetFlowSelector 在所有步都认为 T3 的 delta_progress/delta_cost 最优 |
| budgetflow_full_loose | 0% | 0% | 100% | 同上 |
| budget_only_tight | 0% | 100% | 0% | BudgetOnlyStepRouter 无 T3 代码路径 |
| budget_only_loose | 0% | 100% | 0% | 同上 |

**含义：**
- `budgetflow_full` 在当前 5 easy task 上 ≈ `all_pro` + routing overhead（bf-T $0.53 vs all_pro $0.47，+12%）。"tight" 和 "loose" 区分被 T3 独占行为稀释。
- `budget_only` 永远不用 T3 → 两个 repair_fail（django-10924, sympy-18057）和一个 budget_fail。T3 能在 4-7 turns 解决的题，T2 花 45-67 turns 仍失败。
- 这不是参数问题——是 `BudgetOnlyStepRouter`（policies.py:32-64）架构上不给 T3。需要在 `budget_pressure < 0.15` 时给 budget_only 开 T3 窗口。
