## Part A — What Was Wrong in Phase O

### A.1 solve_rarity Narrative/Code Inconsistency (FIXED)

**Problem:** Phase O's `profile_solve_rarity` formula `1.0 + 4.0 × (1-r)^2`
gave the highest value (5.0) to no-one-solved tasks (r=0), but the report text
said "no-one-solved less informative." The formula and narrative contradicted.

**Root cause:** The formula was inherited from old reasoning about "hard tasks
are valuable," but no-one-solved tasks are not discriminative — they don't
separate good strategies from bad ones.

**Fix:**
- Removed `solve_rarity` from PROFILES
- Added `discriminative_rarity`: formula `1.0 + 4.0 × r × (1-r)`, peaks at r=0.5 (2.0), low at both extremes (1.0 for r=0 and r=1)
- Added `unsolved_difficulty`: formula `max(avg_cost, 0.01) × (2.0 - resolve_rate)`, explicitly labeled as ceiling/hard-task candidate
- Updated `combined` to use discriminative_rarity instead of old solve_rarity
- Tests added: peak-at-moderate-rarity check, old key removed check, ceiling-candidate labeling check

### A.2 Directory-Scan Without Allowlist (FIXED)

**Problem:** `scan_task_universe()` scanned all `data/runs/*.jsonl`, with no
checker-clean allowlist. Future dirty runs could silently enter the matrix.

**Fix:**
- Created `docs/reports/value_matrix_clean_runs.json` — explicit manifest listing 029/030/031 with row counts, strategies, why_clean, and source reports
- Added `--manifest` CLI flag to `value_matrix.py`
- `scan_task_universe(data_dir, manifest=...)` now supports manifest mode: only allowlisted files enter, missing files fail fast, unlisted files skipped
- Manifest metadata embedded in artifact under `meta.manifest`, `meta.manifest_runs`, `meta.source`
- Backward compatible: no `--manifest` → legacy directory scan

## Part D — Localization Progress Diagnosis

### D.1 Root Cause

`has_progress` is always False for LOCALIZATION (0/215 turns) because the
runtime progress signal only fires on file **modifications** (REPAIR/VALIDATION
stages). During LOCALIZATION, the agent runs bash commands to explore/read
files — it does not modify them, so the progress detector never fires.

**Trace fields checked:** bash_digest, assistant_content_head, tool_call_summary,
agent_phase, progress_reason. No field tracks "files opened/read." The trace
captures what the agent did but not whether it found the right files.

### D.2 Offline Diagnostic Results

File paths extracted from `bash_digest` and `assistant_content_head` via regex:

| Metric | Value |
|--------|-------|
| Total LOC turns | 215 |
| Turns with identifiable files | 136 (63.3%) |
| Gold patch available | No |

This is a **lower bound** — some file references may not be captured by the
regex. 63.3% is the minimum; the actual file-exploration rate is likely higher.

**Recommendation:** Option A. Adding `touched_file_paths` to traces is a
one-line change in the runtime bash executor. This diagnostic proves the
signal is recoverable.

## Part E — Progress De-Bias Plan

### E.1 Within-Task Matched Comparison

Raw T2 vs T3 rates conflate tier effect with task difficulty. The matched-task
approach groups turns by (stage, task) and only compares T2/T3 within the same
task:

| Metric | Value |
|--------|-------|
| Comparable pairs (same task, both T2 and T3) | 23 |
| T3 > T2 (T3 better) | 4 |
| T3 < T2 (T3 worse) | 8 |
| Ties (no difference) | 11 |

**Interpretation:** Even within the same task, T3 shows lower progress rates in
most cases (8 of 12 non-tie pairs). This confirms within-task selection bias:
the agent escalates to T3 on harder subtask phases. **Tier choice within the
same task does not consistently improve progress.**

### E.2 What a Full De-Bias Requires

1. **Forced-tier randomization:** Assign some turns to T2/T3 randomly rather
   than by router decision. This breaks the correlation between tier assignment
   and turn difficulty. Requires paid API calls.

2. **Replay calibration:** Replay public SWE-bench trajectories through the
   BudgetFlow router to build a progress table from non-BF data. This avoids
   the selection-bias confound without randomization. No paid calls needed
   but requires public trajectory data.

3. **Stage_blind ablation:** Run with `w_i=1` (all stages equal weight) to
   measure how much of the routing benefit comes from stage-awareness vs
   just having multiple tiers.

### E.3 Minimum Data for Meaningful De-Bias

- 3+ tasks with ≥20 turns in both T2 and T3, same stage
- Current data: only REPAIR has enough (9 tasks with both T2 and T3), LOCALIZATION has 10 but all rate=0
- Need: 30+ tasks for statistical power in within-task delta comparison
