### 活文档放 `paper1/docs/`

直接放在 `paper1/docs/`，不加子目录：
- `CONTEXT.md`, `handoff.md`, `progress.md`, `experience.md`
- `compare.md`, `paper1_concept.md`, `paper1_design.md`

### 当前报告放 `paper1/docs/reports/`

用数字命名，无歧义：
- `001.md` ← 重命名 `next_agent_report.md`
- `002.md` ← harness 调查报告
- `003.md` ← 本文件
- `result1.md` ← 合并进 001 或重命名为报告中引用的格式

### 历史报告放 `paper1/docs/archive/reports/`

从 git log 中可以看到之前有很多报告被删除了（commit `105edc6` 的前身 `4ce43dd` 删除了 12 个报告/结果文件）。如需恢复：
- `paper1/docs/archive/reports/` ← 恢复并归档旧报告
- `paper1/docs/archive/results/` ← 归档旧实验结果

### 实验产物放 `paper1/data/runs/`

保持不变。当前已有 `archive/` 子目录。

### 草稿/笔记放 `paper1/docs/notes/`

新建目录，用于不成熟的思考和草稿，与正式报告区分。

### external 说明放 `external/README.md`

新建文件说明：
- `mini-swe-agent/` 是什么、为什么锁定 commit
- `SWE-agent/` 是什么、有什么对照价值
- `PINNED_COMMIT` 的含义

- Purpose: BudgetFlow runtime dependency (agent loop, model interface, parsers)

- 不要轻易 unpin — parser/agent loop 行为可能随版本变化

## 9. 需要主 agent / 用户决策的问题

| 问题 | 选项 | 影响 |
|------|------|------|
| **是否恢复并归档旧报告？** | 从 git 历史恢复 vs 永久删除 | 保留可能有助于回溯历史上下文；删除减少噪音 |
| **报告用什么命名？** | 纯数字 (`001.md`) vs 描述性 (`harness_investigation.md`) vs 混合 | 数字：简洁、有序；描述性：含义清晰 |
| **是否归档旧 scripts？** | 恢复并保留 vs 永久删除 | GPT-5.3/T4/auto_v2 脚本已过时但可能包含有用的 CLI 模式 |
| **`paper1_concept.md` (77KB) 和 `paper1_design.md` (22KB) 是否拆分？** | 保持原样 vs 拆成多个文件 | 大文件难维护但包含上下文连贯性 |
| **`misc/` 目录是否清理？** | 检查内容然后删除 vs 保留 | 未知内容 |
| **`logs/` 目录是否归档旧日志？** | 保留近 30 天 vs 全部保留 | 日志会积累 |
| **data/runs/ 旧实验 JSONL 是否归档？** | 保留在 runs/ 下 vs 移动到 runs/archive/ | 当前 archive/ 只有 2 个条目 |
| **是否合并 paper2/ paper3/？** | 保留作为占位 vs 删除 | 未来使用则保留 |
