## Part A — P0 Value Matrix Lookup Fix

### A.1 Root Cause

`_init_value_observability()` read `artifact["matrix"][profile]` — but the `matrix` key is
empty in 048+ artifacts. Real data lives under `artifact["tasks"][instance_id]["values"][profile]`.

The old schema (used for 046 and earlier) was `artifact["matrix"][profile][task_id] = {"value": X}`.
The new schema (048+) is `artifact["tasks"][instance_id]["values"][profile] = X`.

Because `artifact["matrix"]` was always `{}` in new artifacts, the lookup always failed silently,
causing every row to get `value_source=default_equal`, `task_value=1.0` — regardless of the
actual difficulty profile values.

**Impact on 049 smoke report:** All 4 rows showed `value_source=default_equal` and `task_value=1.0`.
The report's RVPD numbers ($9.90 BO, $12.76 BF) were ~10x inflated.

### A.2 Fix

Modified `_init_value_observability()` to:
1. Try current schema first: `artifact["tasks"][instance_id]["values"][profile]`
2. Fall back to legacy schema: `artifact["matrix"][profile][task_id]`
3. Report `value_source=missing_profile_fallback` when profile is missing (instead of silently
   falling to `default_equal`)

Three new tests added in `test_value_observability.py::TestCurrentSchema`.

### A.3 Corrected 049 Rescore

| Strategy | Resolved | Cost | Equal RVPD | Difficulty RVPD | Real Difficulty RV |
|---|---|---|---|---|---|
| budget_only_tight | 2/2 | $0.2021 | $9.90 | $0.81 | 0.1632 |
| budgetflow_full_tight | 2/2 | $0.1568 | $12.76 | $1.04 | 0.1632 |

**049 report had equal profile RVPD ($9.90/$12.76) — corrected difficulty RVPD is $0.81/$1.04.**
BF still beats BO (28% better RVPD), but the absolute values are much lower because
sympy tasks have difficulty values of 0.066-0.097 (not 1.0).

**Support for claims:**

  is identical. RVPD differences reflect cost savings, not value-driven allocation.
