BudgetFlow — Related Work 与本周进展

本文研究：一批任务共享硬预算时，预算如何按预注册价值、Task Effort、Model Fit 和模型价格流动。

(1) Claims

Claim 1 Value-Aware Budget Allocation

同一共享硬预算下，BudgetFlow 最大化 Yield（预注册价值 × 验证结果）和 Yield per Dollar。
两层机制：Budget Regime Compiler（预运行编译共享硬预算） + BudgetFlow Runtime（运行时在预算内分配模型机会）。

Claim 2 机制解释

解释 Claim 1 为什么成立——任务级选型、Tier Boundary Selection、stop-loss、shared ledger、memory——在诊断控制下改进或保持 Yield/Dollar。不是第二个独立产品声明。

(1.2) ModelFit — 从历史证据推导模型适配性

ModelFit 是 AllocationContext 三个输入之一（Task Value / Task Effort / Model Fit）。当前 value matrix 不包含 per-task model_fit，运行时不能全靠 catalog 0.24 vs 0.25 这种几乎一样的先验。干净的历史 JSONL 提供了可推导的 per-tier 效率信号。

推导公式

fit[tier] = task_effort × per_turn_cost[tier] / observed_total_cost[tier]

来自干净完成行（非 budget_exhausted）的直接观测。来自 budget_exhausted 行的是 上界——真实 fit ≤ 此值，用于惩罚该 tier。

从 6×5 数据推导（sympy__sympy-16988 为例）

证据行tiertotal_cost状态推导
bare_t2_baseline2$2.30budget_exhausted fit ≤ 23.35 × 6.41 / 2.30 ≈ 0.065（上界，真实更低）
bare_t3_baseline3$0.2745pass fit ≈ 23.35 × 32.04 / 0.2745 ≈ 2.73 → clamp to 1.0

聚合规则

有历史证据的 tier：取 median(fit 观测值)。如该 tier 有 budget_exhausted 证据则取 min(median, min(上界))——真实 fit 不能高于上界。

仅有 censored 证据的 tier：保守惩罚 0.5×，fit = min(上界) × 0.5。

无证据的 tier：回退到 catalog progress_score，trace 标记为 low confidence。

跨任务泛化：不含 task-id 特殊逻辑，不含 SWE-bench 专有规则。同一推导逻辑可用于任何 workload 的干净历史 JSONL。

集成路径

Budget Compiler：auto-estimate 历史 JSONL → fit_overrides → _cold_start_cost_estimate 使用 derived fit_ratio 替代 catalog 0.25/0.24。补偿后 T2 cold-start 投影显著上升（fit_ratio 从 ~1.04× → ~9×），编译器不再"几乎不变"。

Task-Level Router：build_routing_context 接受 model_fit_override → 注入 AllocationContext.model_fit → _expected_total_cost = effort / fit × per_turn_cost 使用 derived fit。T2 fit << T3 fit → T2 总预期成本 >> T3 → 选择 T3。

Budget-exhausted 惩罚：仅 censored 证据的 tier 拿到 0.5× conservative penalty → 对下次 compile 施加更强 T2 成本估计。

OpenSquilla / Claw-SWE-Bench：强工程系统，但不是 Claim 1 的替代

结论：OpenSquilla 对 BudgetFlow 构成 Claim 2 机制级压力，但没有覆盖 Claim 1 的核心问题。它证明工业界和开源系统已经认真在做 token-efficient agent、per-turn learned routing、cost accounting、tool compression、cache continuity 和 diagnostics；因此 BudgetFlow 不能把 novelty 放在“会路由”上。BudgetFlow 必须把自己的贡献钉在：固定任务集 + 共享 hard budget + 预注册 Task Value + verified outcome → 最大化 Total Resolved Value。
系统它做得强的地方对 BudgetFlow 的威胁BudgetFlow 的独立空位我们应吸收/引用
OpenSquilla 一个完整的 token-efficient personal-agent runtime。README 明确说本地 router 把每个 turn 发给 cheapest capable model；SquillaRouter 是本地 LightGBM + ONNX classifier，按 length/language/code/keywords/semantic embeddings 在 C0-C3 四档间选择，并可影响 reasoning level、prompt policy、fallback、cache-continuity diagnostics。它还持久化 sessions、usage/cost、diagnostics、tool compression 和 prompt-cache continuity。 威胁“BudgetFlow 只是模型路由/省 token”的弱叙事。OpenSquilla 的 PinchBench 表展示：OpenSquilla 用 router 在 25 tasks 上接近 OpenClaw 分数，但总成本大幅更低。这说明 reviewer 会合理质疑：你们是不是只是复刻一个 per-turn learned router？ 不是同一个优化问题。OpenSquilla 优化单个 agent session/turn 的 cost-per-usefulness；没有看到它维护一批异质任务共享的硬预算池，没有 pre-registered task value，也没有在 fixed batch 下以 verified Total Resolved Value 为目标做 cross-task allocation。 把它作为强 engineering related work 和 Claim 2 baseline inspiration：turn-history-aware router、reasoning/prompt policy、tool compression、cache continuity、cost view、diagnostics。论文中应明确：OpenSquilla 说明 routing/context controls 重要；BudgetFlow 研究的是这些控制在 shared-budget value allocation 里的审计问题。
Claw-SWE-Bench 它把 agent harness 可比性和污染控制做得很硬：同 prompt、禁网络答案、future-commit stripping、runner-side patch collection、per-instance isolation，并用官方 SWE-bench harness evaluation。它还支持多个 “claw” runtime，方便 harness-to-harness 比较。 威胁我们的 evaluation hygiene。如果我们说自己是 SWE-bench 风格证据，就必须能解释 harness trust、leakage、patch collection、trace/audit、provider failure 处理，否则会显得比它幼稚。 它评测不同 agent harness 的解决率和污染控制；BudgetFlow 研究在同一预算约束下如何分配 model opportunities。Claw-SWE-Bench 可以成为更强的 future evaluation substrate，但不是 value-aware shared-budget optimizer。 直接吸收它的 hygiene 标准：禁网络答案/泄漏扫描、runner-side patch collection、future-commit stripping、per-instance isolation、official harness crosscheck。Related Work 中承认它提升了 agent benchmark 可比性，BudgetFlow 则在这种可比性之上研究预算治理。
审稿人防线：如果 reviewer 说“OpenSquilla 已经做 same budget, more capability”，回答不能是“它不相关”，而是：它是强 per-turn/session routing system；BudgetFlow 的实验问题是 batch-level constrained allocation。我们应该把 OpenSquilla 当作强 baseline 思想来源，甚至未来可以把 SquillaRouter-style router 接入 BudgetFlow，比较 same router outside BudgetFlow vs same router inside shared ledger/value allocation。这样不会贬低 OpenSquilla，也不会把 BudgetFlow 退化成普通 routing。

(3) 价值与泛化性

1. 泛化性在抽象，不在参数。预算/价值/价格/ModelFit 都抽象成可预注册、可审计、可替换的输入，不靠特定 SWE-bench 参数。

2. Compiler 替代手工拍预算。由任务集、Value Matrix、catalog 和校准证据共同生成 hard cap，而不是事后改数。

3. 调参只调抽象规则。调 target utilization、价格 catalog、value source、ModelFit 先验——不能针对某个 benchmark task 开后门。

4. 可迁移。同一套预注册→编译→运行→审计流程可迁移到其他任务域，只需替换 value source、catalog 和历史证据。

核心结论：shared ledger + stop-loss 27% 省钱已验证。task-level 方向对（YPD $3.21 > enterprise $2.83），ModelFit 推导修复方向明确。bare_t2 吞预算证据直接支撑 Claim 1 的 shared ledger 必要性。
