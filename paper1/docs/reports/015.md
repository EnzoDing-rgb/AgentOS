## Analysis

### Ceiling tasks

sympy-18189 and sympy-18057 fail on ALL 5 strategies including all_pro (GPT-5.4). These are genuinely hard tasks beyond current model capability — not routing failures.

**Effective pool (3 solvable tasks):** If we exclude the 2 ceiling tasks, pass rates become:
- all_pro: 3/3 (100%), $0.275
- bf_loose: 3/3 (100%), $0.486
- bf_tight: 2/3 (67%), $0.462
- bo_loose: 2/3 (67%), $0.400
- bo_tight: 2/3 (67%), $0.218

### Routing quality

**bf_loose vs bf_tight on django-10924**: This is the discriminative case. bf_loose solves it (22t, $0.16) while bf_tight fails (27t, $0.24). The key difference: bf_loose escalates to T3 at steps 5, 18, 19, 20 — enough T3 exposure to find a working patch. bf_tight also escalates to T3 (steps 5, 23-25) but the tighter budget constraint limits T3 turns.

**bf_loose matches all_pro on pass rate (3/5), but costs 2× ($0.96 vs $0.50).** On this easy pool, the T2 detour adds turns without adding solved tasks. The value proposition of BudgetFlow only materializes when:
1. Pure T2 can solve most tasks (making all_pro's per-task cost too high)
2. Some tasks NEED T3 rescue (making pure T2 insufficient)

Current pool of 3 solvable + 2 ceiling doesn't exercise this middle ground.

### budget_only T3 gap

Both budget_only strategies remain 100% T2. The `policies.py` T3 window (added for `budget_pressure < 0.15 and n >= 3`) didn't trigger — likely because `n` didn't reach 3 in the right pressure range, or the condition was too narrow. budget_only_loose's sympy-18621 failed with `budget_fail` (cap exhausted at 40t), where one T3 turn could have changed the outcome.

## Known Issues

1. **bf_loose costs 2× all_pro on easy pool.** T2 detour overhead doesn't pay off when T3 can solve everything quickly. Need mixed-difficulty pool to demonstrate value.

2. **budget_only still 100% T2.** T3 window in policies.py too narrow. Need `budget_pressure < 0.20` or a turn-based trigger.

3. **bf_tight T2 cap too aggressive.** `_budgetflow_max_tier()` caps at T2 by default, only allows T3 when `last_backend` was T3. This creates a chicken-and-egg problem: can't escalate to T3 unless already on T3. Should allow T3 based on pressure/stagnation signals too.

4. **5-task pool too small and too easy.** sympy-14774 solved by everything in 6-14t. Only django-10924 discriminates between strategies.

5. **T1 still skipped.** No data on qwen3-coder-flash capability.
