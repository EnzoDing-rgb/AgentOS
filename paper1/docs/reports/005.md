## 6. Requests Readiness

**Not ready for gold sanity yet.** Here's why:

1. **RequestsHAdapter is a no-op**: `map_test_name()` returns `None`, `pytest_env()` returns `{}`, `apply_compat()` does nothing. This is documented in 004.md: "RequestsHAdapter is a placeholder. Gold probe on requests tasks would likely need its own compat."

2. **Old Python 2/3 era code**: Requests base commits are from ~2013-2015. Python 3.11 will likely hit compatibility issues:
   - `collections.abc` imports (partially covered by `apply_python_compat` in local_harness)
   - `cgi` module removal (Python 3.13, not an issue on 3.11 yet but close)
   - Potential `urllib3` / SSL compatibility with old requests versions

3. **High P2P counts**: All 6 requests tasks have 60-142 P2P tests. This means long harness eval times and more surface area for environment-driven false P2P failures.

4. **No repo worktree cached**: `paper1/data/repo_cache/worktrees/` has `django__django` and `sympy__sympy` but no `psf__requests`. First clone will be slow on NFS.

5. **No gold sanity evidence**: Unlike SymPy/Django (3/3 PASS), zero requests gold probes have been run.

**What would be needed to enter Requests gold sanity:**
- Run a single gold probe (e.g., `psf__requests-3362`, smallest F2P=1, P2P=75)
- Diagnose any failures (likely env compat issues)
- If compat needed, implement in `RequestsHAdapter.apply_compat()`
- Only after gold PASS, consider model probes
