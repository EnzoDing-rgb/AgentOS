## 2. Bugs Found and Fixed

### 2.1: BFV Missing from Strategy Allowlists (Phase AB)

**Impact:** BFV did not receive progress escalation (`_apply_progress_escalation`) or adaptive floor protection (`_reserve_with_downgrade`). BFV routed through BFC's allowlist paths instead, meaning it could get stuck at T2 without escalation or floor protection.

**Fix (mini_swe_proxy.py):**
- `_apply_progress_escalation` L829: Added `"budgetflow_value_aware"` to strategy tuple
- `_reserve_with_downgrade` L929: Added `"budgetflow_value_aware"` to adaptive floor check
- Also verified BFV in `query()` rescue forced_tier check and `_apply_gold_edit_repair_guard` tier-limit check

**Tests (test_phase_ab_antispin.py):** 4 source-code audit tests verify BFV presence in each allowlist by AST-parsing the method source.

### 2.2: HTTP Timeout Retry Loop (Phase AA)

**Impact:** `litellm.completion()` had no timeout parameter. When an API call timed out, the `Timeout` exception was caught by tenacity's retry wrapper and retried 10× with exponential backoff (4s → 8s → 16s → 32s → 60s...). Each step could stall for up to 50 minutes before failing.

**Fix (mini_swe_proxy.py):**
- Added `timeout=300` to `litellm.completion()` call
- Created `_ProviderTimeoutError` wrapper exception
- Updated `_query()` inner function to detect timeout exceptions (by name and message) and raise `_ProviderTimeoutError`
- Added `_ProviderTimeoutError` to `retry()` abort_exceptions

**Tests (test_phase_ab_antispin.py):** 5 tests verify timeout/connection error detection and non-timeout exclusion.

### 2.3: BFC Conservation Lockout Misclassification (Phase AA)

**Impact:** When conservation factor blocked T3 access and agent stagnated at lower tiers with budget remaining, failure was classified as `protocol_fail` instead of `budget_fail`. This misattributed BudgetFlow's own conservation mechanism as an agent protocol error.

**Fix (failure_classification.py):**
- Added `_is_conservation_lockout()` detector: checks stagnation exit + conservative/value_aware routing + budget not exhausted + no patch extracted
- Updated `classify_failure()` to check lockout before infra_fail
- Updated `build_verdict()` to override axis to `budget_fail` with subtype `conservation_lockout`

**Tests (test_failure_classification.py):** 10 tests covering detection, classification, verdict axis, BO exclusion, BFV inclusion, budget-exhausted exclusion, patch-extracted exclusion, PASS exclusion, non-stagnation exclusion.

## 7. Remaining Risks

1. **Billing guard instability (dashscope T2):** BadRequestError on `qwen3-coder-plus` killed 2 of 15 rows. This is a provider-side issue. Mitigation: T1 (qwen3-coder-flash) was skipped in pool, so there's no fallback when T2 goes down. Consider enabling T1 as a degraded-mode fallback.

2. **Conservation lockout not observed in vivo:** The 10 lockout tests pass but we haven't seen the pattern in this specific run. Previous runs (055_3x3_v2, 056_5x1_v1) showed it reliably. The billing guard masked it here.

3. **BO T3 cost on 20212:** BO spent the full $0.50 cap on 20212 (46 turns, 9% T3). Without conservation or value awareness, BO burned budget on T2 retries. BFC and BFV also hit the cap on this task but with similar costs — the per-task cap worked as a hard stop.
