## 1. Executive Summary

Phase X fixes the P0 value observer bug discovered in 053, runs corrected paid experiments (2×3 + 2×5) with proper value matrix, and performs proxy noise robustness analysis.

**Verdict: BFC does NOT outperform BO on final RVPD. Both strategies achieve 4/5 pass with identical cost ($0.75) and near-identical RVPD (BO 0.736 vs BFC 0.735).** Proxy noise analysis confirms that the observed difference is within the noise floor — winner flips at ±10% noise.

## 6. Turn Trace Audit (Task F)

### 6.1 ConservativeSelector Failure Mode

BFC on sympy-17630 reveals a fundamental design tension:

1. **Budget conservation is task-agnostic**: Conservation factor increases with budget pressure regardless of task value. The last task in a batch always faces the highest conservation factor, even if it's the highest-value task.

2. **At p > 1.0, T3 is locked out**: With conservation factor >2.05, the T3 upgrade threshold exceeds 1.0, making T3 upgrades impossible. The agent grinds T2 indefinitely without progress.

3. **Missing value awareness**: The selector has no access to `task_value`. It can't know that sympy-17630 (tv=0.548) is worth spending remaining budget on.

### 6.2 routing_stage Coverage

The `routing_stage` field (`localization`/`repair`) is populated in 2×5 traces but empty in 2×3 traces. The 2×5 sympy-16988 BFC trace shows:
- Steps 1-9: T2 for localization (7) + initial repair (2)
- Steps 10-15: T3 for repair (6)

This pattern matches the intended Tier 2 claim: T2 for localization, T3 for hard repair.

### 6.3 BO Front-Loads T3

BO uses 100% T3 on the easiest task (sympy-13480) at near-zero budget pressure (0.01-0.12). This confirms Phase V's finding that BO is a false baseline — it front-loads expensive T3 when budget is abundant and under-invests in hard tasks.

## 8. Claim Impact

### Tier 1: Value-Driven Allocation
**MIXED.** BFC's T3% is value-correlated for tasks 1-4:
- 2×3: 20% → 20% → 62% (value-correlated ✓)
- 2×5: 10% → 19% → 18% → 53% (value-correlated ✓)

BUT both strategies fail the highest-value task (sympy-17630, tv=0.548). BFC's conservation mechanism locks out T3 on the last task when budget pressure is highest — exactly when a high-value task needs it most.

**Root cause**: Conservation factor is value-blind. It treats all tasks equally regardless of task_value.

### Tier 2: Routing Efficiency Reduces Waste
**POSITIVE with caveat.** BFC avoids BO's wasteful T3 front-loading on easy tasks (10-20% T3 vs 100%). On sympy-16988, BFC's strategic T3 deployment (53% T3) achieves 2.8× cost reduction vs BO's T2 grind.

BUT BFC's conservation mechanism over-restrains T3 on the last high-value task. Total T3 usage (20% vs BO's 15%) does not translate to better final outcomes.

### North Star: Maximize RVPD Under Hard Budget
**NOT SUPPORTED by final data.** BO and BFC are statistically indistinguishable on RVPD:
- 2×3: BFC +2.6% (likely noise with N=3)
- 2×5: BO +0.1% (within noise floor)

**The proxy noise analysis is working as designed — it correctly identifies that the observed differences are not robust.**

## 9. Design Insight: Value-Aware Conservation

The ConservativeSelector needs value awareness. A value-aware variant would:

1. Accept `task_value` as input to the selector
2. Scale the conservation factor inversely with task value: high-value tasks get lower conservation (easier T3 access), low-value tasks get higher conservation
3. Bound conservation so T3 is never fully locked out (max factor < threshold to keep T3 accessible)

Proposed formula:
```
conservation = 1.0 + max(0, p - 0.3) * 1.5 * (1.0 / max(task_value_normalized, 0.1))
```

This is deferred to Phase Y.

## 10. Limitations

1. **Small sample**: 10 task-runs in 2×5, 6 in 2×3. Statistical confidence requires larger experiments.
2. **Sympy-only tasks**: All 5 tasks from sympy. No cross-repo validation.
3. **Single value profile**: Only tested `unsolved_difficulty`. Other profiles may yield different conclusions.
4. **BO is a weak baseline for T2 claim**: BO's front-loading of T3 on easy tasks is clearly pathological. A fairer T2 comparison would be BO2 (T2-only).
5. **Task order matters**: BFC's conservation factor depends on cumulative budget spent, so task execution order affects T3 availability. This is a confound.

## 11. Next Steps (Phase Y)

1. **Value-aware conservation**: Modify ConservativeSelector to accept task_value, scale conservation inversely with value
2. **BFC vs BO2 comparison**: BO2 (true T2-only) is the correct baseline for Tier 2 claims
3. **Larger experiments**: 5+ tasks with cross-repo task pool
4. **Task order randomization**: Control for order effects in shared-budget experiments
5. **Ablation**: Test conservation slopes [0.5, 1.0, 1.5, 2.0] to find optimal
