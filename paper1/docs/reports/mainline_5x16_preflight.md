## Local evaluation infra audit (Part A)

### Findings

1. **SymPy leakage**: None found. The shared `local_harness.py` flow dispatches
   to `RepoHarnessAdapter.for_task(task)` based on repo slug. No task-id
   branching exists. The only repo-specific string is a cosmetic log message
   `"(sympy ~3-8 min, streaming below)"` in `_pip_install_editable`.

2. **DjangoHAdapter gaps** (all fixed):
   - **INSTALLED_APPS missing**: `tests/test_sqlite.py` doesn't set
     `INSTALLED_APPS`. The official Django test runner (`tests/runtests.py`)
     adds contrib apps dynamically, but pytest skips that step. Any test
     importing a Django Model raised `RuntimeError: Model class ... doesn't
     declare an explicit app_label`. Fixed by injecting standard contrib apps
     (admin, auth, contenttypes, sessions, messages, staticfiles) in conftest.py
     before `django.setup()`.
   - **DATABASES NAME missing**: Older Django versions of `test_sqlite.py`
     omit the `NAME` key from `DATABASES`. TestCase (database-requiring) tests
     raised `ImproperlyConfigured: Please supply the NAME value`. Fixed by
     setting `NAME=':memory:'` for in-memory SQLite databases in conftest.py.
   - **Test database not migrated**: Even with NAME set, TestCase tests
     failed with `OperationalError: no such table: auth_user` because the
     test database had no tables. Fixed by calling
     `call_command('migrate', run_syncdb=True)` after `django.setup()` for
     in-memory databases only.

3. **Django-native test runner path** (new): Added `build_test_command()` to
   `RepoHarnessAdapter` interface. Default implementation uses pytest.
   `DjangoHAdapter` overrides it to use `tests/runtests.py` (Django's
   DiscoverRunner), which handles app registration for inline test models that
   pytest+conftest cannot. This unblocks tasks previously excluded for
   inline-model failures. The adapter converts pytest node IDs to Django
   dotted test labels automatically. `run_pytest()` adds the repo root to
   `PYTHONPATH` so `tests.test_sqlite` is importable regardless of which
   runner is used.

4. **Remaining limitation — inline test models (resolved for 3/4)**:
   The Django test runner path resolves inline test model issues for
   django-11099, django-11049, and django-11001. django-10914 still fails
   due to a pass_to_pass test database loop (98 pass_to_pass tests, likely
   Python 3.11 / Django 3.0.dev compatibility). This is a test runner
   compatibility issue, not an inline model issue.

5. **Requests adapter**: `RequestsHAdapter` is a no-op stub. No Requests
   tasks are in the current batch. No changes made. No risk.

### Files changed

- `src/budgetflow/local_harness_adapters.py`:
  - `RepoHarnessAdapter.build_test_command()`: new method, default pytest
  - `DjangoHAdapter._pytest_node_to_django_label()`: pytest node ID → Django test label
  - `DjangoHAdapter.build_test_command()`: uses `tests/runtests.py` for Django tasks
  - `run_pytest()`: uses adapter's `build_test_command()`, adds repo root to `PYTHONPATH`

  - Added `_DJANGO_CONFTEST_MARKER` for safe idempotent re-patching.

No changes to BudgetFlow routing, budget, memory, strategy, or model tier
layers. No task-id if/else branches added.

## Residual risks

1. **Low budget utilization (13.5%)**: The calibrator flags the budget as too
   loose but issues PASS_WITH_DIAGNOSTIC_OVERRIDE. This is intentional — the
   hard cap follows the frozen plan cap sum for symmetry across
   enterprise_router and budgetflow_same_router strategies. The budget is
   still binding for those strategies.

2. **Zero-history Django tasks (16046, 15388)**: Both are 2-line patches with
   minimal test surface and confirmed gold sanity PASS under runtests.py path.
   Bootstrap difficulty estimates are low (8.98, 10.13), but the conservative
   base_cap of 0.22 provides adequate headroom.

3. **django-10914 excluded**: Fails pass_to_pass with test database loop
   (Django 3.0.dev + Python 3.11 compatibility). Individual pass_to_pass
   tests pass fine. Not a blocker — 4 Django tasks provide sufficient 2-repo
   signal.

4. **Django test runner path**: Uses `tests/runtests.py` which is present in
   all tested Django versions (3.0.dev through 4.2.dev). If runtests.py is
   missing or broken, falls back to pytest. For django-10914 the runner
   itself works (fail_to_pass, fail_after all correct) — only pass_to_pass
   with 98 tests + --failfast fails.

5. **minisweagent import**: Same as 5x14 — test environment does not have
   minisweagent installed. Some trace_fields tests skip on import. Runtime
   behavior verified through focused tests.
