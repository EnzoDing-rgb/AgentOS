## Infra and Runtime Findings

1. Continual learning is active.

   Learned caps changed between 062 and 062b because successful outcomes are now written into `auto_budget_memory.jsonl`. This is expected product behavior, but it means exact reruns are non-stationary unless the memory file is frozen.

2. Gold-edit / worktree fallback is still late.

   Several successful rows pass via worktree patch after long repair loops. BFC's 16988 row uses 41 turns; BFC's Django row uses 31 turns. This keeps hurting Tier 2 cost.

3. BFV decision quality is unstable.

   On 062, BFV solved all three tasks. On 062b, with value multipliers still active, BFV solved only the low-value task. The next debugging pass should compare BFV patches and tier choices against BO/BFC on 16988 and Django.

   Patch audit supports this as a real repair-quality issue, not just evaluator noise. On Django 10924, BO/BFC produce compact patches around `FilePathField`; BFV computes a local `path` but still passes `self.path`, and also injects irrelevant `path = self.path()` lines into unrelated field classes. On SymPy 16988, BO/BFC make narrow duplicate-removal changes, while BFV changes multiple nearby branches and fails local harness.

4. Fresh JSONL schema needed a compatibility alias.

   New rows had `harness_resolved`, but not top-level `resolved`. Some analysis scripts naturally read `resolved` and misreported `None`. Runtime now writes `resolved == harness_resolved`; checker warns on alias mismatch. Historical JSONL remains immutable and forensic-only where schema is weak.

## Decision

Do not run 3x5 or 3x8 yet.

Next action should be a focused runtime/evaluation debug pass:

- inspect BFV failed patches against BO/BFC passing patches;
- check whether value-aware routing changes model mix at harmful moments;
- tighten or redesign gold-edit evaluation timing only after the failure mode is identified;
- run a small policy-parallel gate after the fix.
