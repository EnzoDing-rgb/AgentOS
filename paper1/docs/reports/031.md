## Methodology Notes

1. **BudgetMemory vs AutoBudget are separate systems.** BudgetMemory learns from JSONL with LOO exclusion (statistical cascade). AutoBudget uses hardcoded `_HISTORICAL_PRIOR` (cold-start table). Both write separate fields to JSONL (`budget_memory_budget_source` vs `budget_prior_source`). The gate metric is BudgetMemory source only.

2. **All 10 rows show `repo_median` because all 5 tasks are held-out.** In a full experiment where some tasks are in training and others held-out, you'd see a mix of `exact_task` and `repo_median`. This run's 100% `repo_median` is correct for the all-held-out design but does not demonstrate the mixed cascade.

3. **sympy-18057 is a budget_fail for both strategies.** The auto-budget cap ($0.12) was insufficient. This task had `harness_resolved=False` in 030 for both strategies as well.

4. **bf-T is more expensive without pass-rate gain.** This mirrors 030 (both 7/10, bf-T more expensive). On easy tasks, bf routing overhead adds cost without adding passes. The rescue on sympy-16988 worked correctly but added $0.12 vs bo-T's direct solve.

## Limitations

- N=5, single run. No repeats — cannot assess variance.
- All held-out → all `repo_median`. Mixed train/test split would show cascade diversity.
- API keys sourced from old `/Lishun` archive `.env` file (not committed).
- `external/mini-swe-agent` symlinked from old archive (not a proper submodule checkout).
- T1 (qwen3-coder-flash) skipped — BudgetFlow's low-tier advantage not tested.
