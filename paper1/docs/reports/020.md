# 020 — BudgetMemory Integration & Fine-Grained Attribution (revised)

## 1. Changes in this revision

### 1.1 P0 Fix: dry-run/gate-only triggering provider preflight

**Bug:** `--budget-memory-dry-run` was placed AFTER `check_required_signatures()` in `main()`,
causing `[preflight] PASS backend=tier1 ...` despite claiming "no API calls."

**Fix:** Reordered `main()` so dry-run exits before provider check:

```
Args → gate-only → task loading → auto-budget → DRY-RUN → sys.exit(0)
                                                         ↓
                                               provider preflight
```

Gate-only (`--budget-memory-gate-only`, `--policy-memory-gate-only`) was already
correctly placed — verified with tests.

### 1.2 Lazy imports: no litellm in dry-run/gate-only

`provider_signature.py` and `adapter/mini_swe_proxy.py` import `litellm` at module
level, which triggers a remote cost-map fetch. Moved heavy imports to call sites:

| Import | Moved to |
|--------|----------|
| `provider_signature.check_required_signatures` | Inside `if not args.no_provider_signature_check:` |
| `adapter.runner.run_mini_swe_task` | Inside `_run_one()` |
| `adapter.backends._selected_t2_backend` | Inside `_required_backends_for_strategies()` |

These three imports are the only paths that pull `litellm` into the module.
dry-run/gate-only no longer import `litellm`.

**Known limitation:** `lite_tasks.py` imports `minisweagent` at module level,
which prints a banner (`👋 This is mini-swe-agent version 2.3.0.`). This is
not an API call, but it appears in gate-only stdout. Acceptable for now.

### 1.3 P1.1 Fix: dry-run old_cap semantics

Old cap resolution priority:
1. `--auto-budget` → `auto_budget` source, comparable
2. Historical JSONL has `estimated_task_cap` / `batch_budget_cap` → `historical` source, comparable
3. `--per-task-cap` → `per_task` source, comparable
4. None of the above → `standard_tight` source, **not_comparable**

Verdict logic (only applied when comparable):
- `actual_median > old_cap * 1.2` → `underbudget` (old cap too low)
- `old_cap > actual_median * 3` → `overbudget` (old cap wastefully high)
- otherwise → `ok`

Dry-run output columns: `task`, `strategy`, `old_cap_src`, `old_cap`, `bm_cap`,
`actual_median`, `verdict`.

### 1.4 P1.2 Fix: TRUSTED_FALLBACK AUDIT section

New section in `offline_replay.py` specifically audits `trusted_fallback` rows
(dynamically via `build_harness_trust()`):

```
=== TRUSTED_FALLBACK AUDIT ===
  trusted_fallback_rows=9
  evidence_complete=9
  no_submission=5
  submitted_same=2
  unknown_offline=2
  NOTE: unknown_offline = patch file paths not accessible in offline replay
  trusted_fallback_pass=9 (PASS with worktree fallback)
```

`unknown_offline` is distinguished from generic `unknown` — it means the
patch comparison cannot be done without access to the original run environment.

### 1.5 Record field naming fix

Old field `budget_memory_source` (misleading — implied cascade level but could
be confused with source file paths) replaced with two fields:

| Field | Meaning |
|-------|---------|
| `budget_memory_source_paths` | Comma-separated JSONL file paths loaded |
| `budget_memory_budget_source` | Cascade level: `exact_task`, `repo_median`, `strategy_median`, `global_fallback` |

### 1.6 BudgetMemory integration (`run_mini_swe_compare.py`)

CLI flags:
- `--budget-memory PATH[,PATH...]` — load BudgetMemory from JSONL
- `--disable-budget-memory` — explicitly disable
- `--budget-memory-dry-run` — compute estimates, print old_cap vs bm_cap, exit (no API)
- `--budget-memory-gate-only` — load + validate + print diagnostics, exit (no API)

Per-row fields written when `budget_memory_enabled=True`:
`budget_memory_source_paths`, `budget_memory_budget_source`,
`budget_memory_estimated_budget`, `budget_memory_predicted_cost`,
`budget_memory_confidence`, `budget_memory_reason`,
`budget_memory_hard_budget_used`, `budget_memory_risk_multiplier`,
`budget_memory_applied`.

Default: OFF. No effect on existing experiments unless `--budget-memory` passed.
