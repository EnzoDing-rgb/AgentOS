### 1.1 Harness trust audit (`observability.py`, `check_run_observability.py`)

New `build_harness_trust(record)` returns per-row:
- `harness_trust`: trusted / **trusted_fallback** / suspicious / invalid / incomplete
- `harness_issues`: list of specific gaps found
- `harness_owner`: harness / model / protocol / infra / none
- **`severity`**: none / **warn** / **blocking**

Trust levels (v2):
- **trusted**: evidence complete, submission patch, no gaps
- **trusted_fallback**: evidence complete, but patch from worktree fallback → severity=warn (不等于无效PASS)
- **suspicious**: PASS with non-blocking evidence gaps (e.g. fail_before missing only)
- **invalid**: PASS with blocking gaps (fail_after/pass_to_pass missing) → severity=blocking
- **incomplete**: FAIL with no patch or incomplete evidence

Severity semantics:
- **warn**: non-blocking gap — worktree fallback (evidence says it's fine), missing test_patch only, etc.
- **blocking**: evidence gap that makes pass/fail unreliable — missing fail_after, missing pass_to_pass, missing model_patch

### 1.2 Verdict observability (`failure_classification.py`, `run_mini_swe_compare.py`)

New `build_verdict(record)` returns per-row:
- `verdict_axis`: pass / model_fail / budget_fail / harness_fail / routing_fail / protocol_fail / infra_fail
- `failure_owner`: none / model / budget / harness / protocol / infra
- `failure_stage`: none / runtime / extraction / localization / repair / validation / test_patch / fail_before / harness
- `evidence_complete`: bool
- `missing_evidence`: list

Verdict axis decision tree: pass → budget_fail → routing_fail → protocol_fail → harness_fail → model_fail / infra_fail.

### 1.4 BudgetMemory (`budget_memory.py`)

**This is an offline learning skeleton. It is NOT yet integrated into run_mini_swe_compare real budget allocation.** The live per-task cap estimation still uses `AutoBudgetEstimator` (auto_budget.py).

```
bm = BudgetMemory.from_jsonl(paths)
est = bm.estimate_task_budget(instance_id, repo="", strategy="",
                              task_value=1.0, hard_budget=None)
```

Estimation cascade: exact_task → repo_median → strategy_median → global_fallback. hard_budget caps the estimate.

### 2.1 9 trusted_fallback PASSes audit

All 9 are worktree fallback patches with complete harness evidence (test_patch=ok, fail_before=fail, model_patch=ok, fail_after=pass, pass_to_pass=pass). None are "false positives" — the harness evidence chain is fully intact. They are marked trusted_fallback (not suspicious) because:
- Evidence says the patch passes all harness checks
- Only the *source* (worktree diff instead of agent submission) differs
- This is a protocol concern (agent didn't properly submit), not a harness concern

### 2.2 8 blocking severity rows

These are FAIL rows with missing harness evidence at critical stages (fail_after not passed or model_patch failed). Not PASS fraud — they're properly recorded as failures with incomplete evidence.
