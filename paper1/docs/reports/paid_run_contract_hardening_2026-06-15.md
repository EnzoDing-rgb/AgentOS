# Paid Run Contract Hardening — June 15, 2026

## Objective

Close the remaining ambiguity between the Budget Regime Compiler and the paid-runner before the next 6x30 staged paid run. The runner should consume a pre-registered budget plan; it should not generate or reinterpret budget regimes at launch time.

## Interface Decisions

- Runtime budget semantics for the paper mainline are fixed: all six strategies use the same policy-local `shared_batch_hard_budget` cap.
- `generation_mode` is the Budget Regime Compiler field. It replaces the ambiguous budget-plan `budget_mode` field.
- `--budget-mode` and `--target-utilization` are removed from the paid runner CLI. `target_utilization` remains only inside `budgetflow.experiments.budget_binding calibrate`.
- Diagnostic model catalogs such as `model_tiers.t3x3.json` require explicit `--diagnostic-catalog` opt-in during paid readiness/run launch.
- Cold-start budget projection now prefers outcome-free frozen-plan cap priors when no clean historical rows exist. Clean historical cost memory supersedes this prior when available.
