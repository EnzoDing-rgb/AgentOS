## Task C: CLI Hardening

### Changes

1. **`--worker-cmd` validation** — `_validate_worker_cmd()` rejects commands missing `{prompt}` or `{output}` placeholders. Prints descriptive error to stderr and exits 1.

2. **Exit codes hardened:**
   - Worker exits zero, status=complete → rc=0
   - Worker exits nonzero, status=failed → rc=1 (was 0)
   - Pause triggered → rc=2 (unchanged)

3. **Security note** in module docstring: `--worker-cmd` executes trusted local commands only.

## Task D: Status/List Polish

### `list` filters

```
list --status STATUS     # Filter by status (pending, running, paused, complete, failed)
list --paused-only       # Show only paused workflows
```

Summary counts always reflect all workflows, not just filtered view.

### `next` command

```
next --issue-id ID       # Print next action based on current status
```

Action mapping:

| Status | Next Action |
|--------|-------------|
| pending | `run --issue-id {id} [--dry-run \| --manual \| --worker-cmd CMD]` |
| running | `inspect worker_output and write codex_review` |
| failed (attempt < max) | `retry allowed — run --issue-id {id}` |
| failed (attempt >= max) | `retry exhausted — mark-failed or escalate` |
| paused | `owner/Codex approval required` |
| complete | `no action — workflow is complete` |

## Remaining Gaps Before Real API / Real Worker

1. **Real Worker adapter** — replace `scripts/autoresearch_fake_worker.py` with a production adapter that invokes Claude Code (or equivalent) on the prompt and writes real outputs. The worker bridge (`--worker-cmd`) already supports any shell command.

2. **Codex automatic review** — `codex_review_fn` callback exists on coordinator but is not wired to the CLI. Currently Codex review is manual (write `codex_review.md` by hand). Could be automated as a separate Codex agent invocation.

3. **Post-gate auto commit/push** — explicitly deferred. Should only be enabled after Codex gate approval is proven reliable on real issues. Currently commits are manual.

4. **Owner approval gate for paid runs** — `ApprovalPolicy.must_stop_before_run()` gate exists and `--paid-3x10 P T` flag triggers pause. But the owner approval workflow (notification, explicit approve, resume) is not yet automated.

5. **Goal-level orchestration** — coordinator operates on individual issues. Multi-issue Goal tracking (issue queue, dependency ordering, Codex-driven sequencing) is not yet implemented.

6. **Resume from crash scan** — `load_state()` works, but no `list --paused-only` automated "scan and report paused workflows" entry point that could be used by a monitoring loop.
