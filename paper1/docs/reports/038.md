## Why `claude -p` Failed (Phase G)

`claude -p` spawns a full Claude Code session with ~10K+ tokens of overhead
(system prompt, tool schema definitions, workspace context, CLAUDE.md
processing). Even with `--bare`, the session setup consumed the entire $0.50
budget before the Worker read its prompt or produced output.

The AutoResearch bridge itself was fine — it correctly invoked the Worker
CLI, tracked attempts, and preserved state. The problem was purely at the
Worker adapter layer: the CLI had too much overhead for small smoke tasks.

## Thin API Worker Design

`scripts/autoresearch_api_worker.py` bypasses Claude Code entirely:

1. Reads the worker prompt + the two docs it references
2. Builds a minimal Anthropic Messages API request (compact system prompt, user message with prompt + docs)
3. Calls the API directly via `requests.post`
4. Writes the model's response text to the output path
5. Appends `AUTORESEARCH_REAL_API_SMOKE:PASS` marker if missing

### Environment Variables

| Variable | Used? | Source |
|----------|-------|--------|
| `ANTHROPIC_BASE_URL` | Yes | `api.deepseek.com/anthropic` (from env) |
| `ANTHROPIC_AUTH_TOKEN` | Yes (fallback) | From env |
| `ANTHROPIC_API_KEY` | Yes (preferred) | Checked first, falls back to AUTH_TOKEN |
| `AUTORESEARCH_MODEL` | Optional override | Not set |
| `ANTHROPIC_SMALL_FAST_MODEL` | Default model | `deepseek-v4-flash` (from env) |

No secrets hardcoded. No API keys printed to stdout (masked to first 8 chars).

### Key Design Decisions

- **No Anthropic SDK dependency** — uses `requests` (already installed)
- **Auth token flexibility** — tries `ANTHROPIC_API_KEY` first, falls back to `ANTHROPIC_AUTH_TOKEN` (the DeepSeek auth format)
- **Model selection** — prefers cheapest available (`ANTHROPIC_SMALL_FAST_MODEL` over `ANTHROPIC_MODEL`)
- **Marker injection** — if the model response lacks the PASS marker, the worker appends it (ensures downstream Codex gate can always check for the marker)

## Remaining Gaps

1. **Codex automatic review** — `codex_review_fn` callback exists on coordinator.
   Currently Codex review is manual. Next step: wire the thin API worker as a
   Codex reviewer (different system prompt, reads worker_output + evidence,
   writes verdict). This closes the last manual step in the loop.

2. **Post-gate auto commit/push** — after Codex approves, automatically commit
   and push accepted changes. Deferred until Codex gate reliability is proven
   on real issues.

3. **Goal-level orchestration** — multi-issue Goal tracking, issue queue,
   dependency ordering. Coordinator currently operates on individual issues.

4. **Owner approval gate** — `ApprovalPolicy` exists but notification + explicit
   approve + resume workflow is not automated.

5. **Worker model selection** — currently hardcoded to prefer
   `ANTHROPIC_SMALL_FAST_MODEL`. Could add per-issue model selection for
   tasks that need more capable models.

## Residual Risks

1. **Model hallucination in worker output** — the LLM-generated worker_output.md
   may contain inaccurate metadata (e.g., this smoke's output claimed model was
   `claude-sonnet-4` but it was actually `deepseek-v4-flash`). The thin worker
   script's stdout is the authoritative source. Codex should cross-check CLI
   stdout against worker output claims.

2. **Single API provider** — currently only Anthropic-compatible endpoints.
   Adding OpenAI-compatible support would make the worker more portable.

3. **No retry on API transient errors** — the thin worker exits 1 on any non-200
   response. The coordinator retry policy handles this (up to max_retries), but
   the worker itself doesn't distinguish transient (429, 503) from permanent
   (401, 403) errors.
