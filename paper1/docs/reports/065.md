## Trace Audit

### Tier 1 positive mechanism

On `sympy__sympy-16988`, BFV had `task_value_multiplier=1.478` and triggered value salvage three times. During the salvage window it patched `sympy/sets/sets.py` and the local harness passed.

BO and BFC both stopped at 12 turns with `stagnation_no_progress`, no patch, and budget remaining. This is the cleanest current evidence that task-wise value can change stop/continue behavior in a useful way.

The BFV patch is compact:

```diff
- args = list(cls._new_args_filter(args))
+ args = list(ordered(set(cls._new_args_filter(args)), Set._infimum_key))
```

### BFV negative mechanism

On `django__django-10924`, BFV spent 30 turns and $0.2573, edited the gold file, but failed `fail_after`. The patch added a callable `path` property but still did not satisfy the task's failing tests.

This is a real repair-quality failure, not an obvious evaluator false negative. BO passed the same task in 8 turns using T3 throughout; BFC passed in 25 turns. BFV was too slow to reach a correct repair under its current value/salvage thresholds.

### Tier 2

BFC does not support Tier 2 in this run. It is more expensive than BO for the same resolved value and pass count.

On Django, BFC eventually passed but spent 25 turns versus BO's 8. On the high-value SymPy task, BFC stopped with no patch like BO.

## Post-Run Infra Bugs Found and Fixed

Historical artifacts were not edited.

1. **Heartbeat race:** multiple policy threads wrote the same `.tmp` file and one final rename failed. Fixed by making `HeartbeatWriter` thread-safe, using per-thread temp paths, and `os.replace()`.

2. **Run identity mismatch:** `--out-stem 065_value_salvage_3x3` still wrote `run_series=compare_3x3` and heartbeat `compare_3x3.heartbeat.json`. Fixed so new rows use concrete `out_stem` as `run_series`; the series base is only for auto-allocation/resume grouping.

3. **Live summary spend aggregation:** per-task/dynamic-cap live summaries displayed the latest row cost as `batch_spent` until batch footer arrived. Fixed to aggregate `sum(task_cost_by_strategy)` during live updates. JSONL and checker totals were already correct.

## Claim Readout

### Tier 1

Partially supported at mechanism level, not at aggregate metric level.

Positive: BFV uniquely resolved the highest-value task through value-aware salvage.

Negative: BFV's aggregate RVPD is lower than BO because it failed Django and spent more overall.

The right conclusion is: value-aware salvage is a promising T1 mechanism, but the current BFV policy still has task-family fragility and threshold/timing issues.

### Tier 2

Not supported.

BFC is value-blind and should remain the Tier 2 ablation, but this run shows no cost-efficiency advantage over BO.
