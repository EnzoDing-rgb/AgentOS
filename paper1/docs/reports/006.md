## 5. Experiment Spec

### Command

```bash
cd paper1 && PYTHONPATH=src:../external/mini-swe-agent/src \
  ../.venv/bin/python -u -m budgetflow.run_mini_swe_compare \
  --no-provider-signature-check \
  --ids sympy__sympy-14774,django__django-12113,django__django-10924 \
  --strategies all_pro,budget_only_tight,budgetflow_full_tight \
  --step-limit 80 --tight 250 --jobs 3 --heartbeat 30 \
  --trace-turns --trace-max-turns 80 \
  --run-series sanity_gold_pass_006
```

### 设计决策

| 参数 | 值 | 理由 |
|---|---|---|
| `--tight` | 250 | 无 frozen_caps.json，手动设。单 sympy all_pro 需 ~85，预算策略预留余量 |
| `--jobs` | 3 | 3 policy 并行，每个 policy 内部串行 |
| `--step-limit` | 80 | SWE-bench 标准步数，足够但不过度 |

### 并行模型

- 3 个 policy 同时启动（`budget_only_tight`, `budgetflow_full_tight`, `all_pro`）
- 每个 policy 内部 3 个 task 串行（共享 BudgetGovernor）
- 每个 task 独立 git worktree，隔离 repo 修改
- 日志显示 3 个 policy 确实并行推进（heartbeat 同时显示 3 条状态）

**无 harness false positive/negative。** P2P 没有出现 false failure。

### 7.2 模型链路

- GPT-5.4 (all_pro): 稳定。定位准确（3/3 gold file found），编辑正确（2/3 repair pass），提交可靠。
- qwen3-coder-plus (budget_only_tight 起点): 可用但会升级到 T3。sympy 任务中 T2→T3 escalation 消耗了全部预算。
- Turn trace 收集正常，forensic summary 字段完整。

### 7.3 Budget 校准

**tight=250 对 3-task 共享池偏小。** 原因：
- `budget_only_tight` 从 T2 起步，sympy 任务内部 escalation 到 T3 后消耗 ~250
- `budgetflow_full_tight` 类似，16 turns 全部用完
- 结果：django 任务在两种 budget 策略下 budget=0，无法运行

这不是 bug，是 budget calibration 需要调整。每个任务大约需要 80-120 的 tight budget（如果 escalation 发生）。3 任务共享需要 ~300-400。

### 7.4 并行稳定性

| 维度 | 状态 |
|---|---|
| Policy 并行推进 | 3 个 policy 确实同时运行（heartbeat 可证） |
| Worktree 隔离 | 有效，不同 policy 独立 worktree |
| Policy 内串行 | 保持（sympy → django-12113 → django-10924 顺序） |
| Resume 稳定性 | **有问题**：首次 kill 后 resume 时 worktree 冲突 |

**Resume 问题根因**: 首次 run 被 kill（exit 137，疑 OOM 或超时）后，worktree 目录残留。Resume 时 `git worktree add --force` 在已存在目录上 crash。这是 runner 的 edge case，不是本次 probe 的设计问题。
