Executed outcome:

- All four strategies reported 0/6 verified resolved, so raw T1 Yield and Yield per Dollar were 0.
- This must not be used as evidence that BFV/BFC are weaker than BO: 17/24 rows
  have host-dependency-contaminated harness evidence, and checker now treats
  them as `HARNESS_INVALID` / blocking infra issues.
- Root cause: local SymPy harness pytest imported host optional dependencies
  (`opik`, `tensorflow`/`keras`/`pandas`/`scipy`) with a broken NumPy ABI. The
  failure was an infra contamination, not a model/routing outcome.
- Fix direction: isolate pytest plugin autoload, treat broken SymPy optional
  dependency imports as unavailable in ephemeral harness worktrees, and keep
  host-dependency-contaminated runs out of default Routing Memory.
- Replay after the harness fix, without mutating historical JSONL, changed 6/19
  patch rows from FAIL to PASS. Replay-corrected diagnostic metrics:
  `budget_only_tight` 2/6, Yield 0.1969, Yield per Dollar 35.87; BFC 2/6, Yield 0.1969,
  Yield per Dollar 31.80; BFV 2/6, Yield 0.1969, Yield per Dollar 22.88; task-level control 0/6.
- Mechanism interpretation after replay: stage-aware BFV/BFC no longer lose on
  pass count, and stage-aware beats task-level on both pass count and cost.
  BFV still spends more than BO/BFC for the same replay-corrected value, mostly
  through extra T2 repair runway on tasks such as 20212, 17630, and 14317. Next
  diagnostics should focus on validation-grounded repair and stop rules, not
  simply "use more T3."
